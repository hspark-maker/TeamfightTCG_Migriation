# 랭크 AI 성장·승급전 설계

작성: 2026-09-10. 2026-09-11 카드별 성장 전달과 일반전 프로필 CSV·스키마·서버 조회 연결 구현. 난이도는 검증 전 초기 곡선이며 원격 데이터는 변경하지 않았다.

## 구현 진행 (2026-09-11)

- `findAiMatch`의 `aiGrowthVersion: 1` 계약 추가. 응답 `cardGrowth`에 카드 ID별 level·limitBreak와 서버가 계산한 HP 보너스·진화·키워드·시너지 해금 스냅샷을 담는다.
- 매치 문서에 카드별 성장·전투 스냅샷·스펙 핀을 고정한다. 같은 txId 재시도는 현재 표를 다시 읽지 않고 기존 응답을 반환한다. `submitMatchResult`는 고정한 적 스냅샷을 재생에 사용한다.
- 클라이언트는 수신한 스냅샷을 카드 ID별로 보관한다. 상대 카드 표시·실제 필드·덱 해시가 같은 값을 사용하므로 셔플 뒤에도 성장 대상이 바뀌지 않는다. 모험·튜토리얼·실제 유저 대전의 성장 경로는 별도로 유지한다.
- 구 공통 `cardLevel` 응답과 기존 매치 결과 제출을 지원한다. 새 계약의 누락·중복·잘못된 성장값은 공통 레벨로 대체하지 않고 거절한다.
- `docs/SpecData/RankAiEncounter_sheet.csv`에 20티어·22덱의 일반전 혼합 성장 136행을 저작했다. 새 계약 매칭은 같은 발행본의 AIDeck·RankAiEncounter를 고정하여 현재 티어의 Normal 프로필만 가중 추첨한다. 후보·프로필이 없으면 공통 레벨로 대체하지 않는다. 선택한 프로필 ID·전투 종류·티어·강조 카드 ID도 매치 문서에 고정한다.
- 서버 전용 `RankAiEncounterRow` 스키마와 에디터 CSV 직접 발행 경로를 추가했다. 클라이언트 동기화 목록과 콘텐츠 major 5는 유지하며 bytes·생성 C#을 거치지 않는다. 현재 AIDeck 공통 레벨은 구 계약 전용이다. 상세 저작 상태는 [성장 프로필 저작 상태](SpecData/RANK_AI_ENCOUNTER_STATUS.md)에 기록했다.
- **후속:** 마지막전 전용 CSV 행·판정·강적/에이스 강조·난이도 검증. 서로 다른 txId의 마지막전 재추첨 방지도 마지막전 구현 범위로 남는다.

검증: TypeScript 빌드·변경 파일 ESLint, 실제 CSV 136행의 티어별 후보·성급 합계·참조·가중 추첨, 서버 성장/매칭/결과 제출 회귀 통과. 전달 구현 시 Unity 참조 기반 C# 컴파일과 클라이언트 전달 68개 검사·서버/C# 덱 해시 일치를 확인했다. 실행 방법은 `Tools/AiMatchGrowthTests/README.md`를 따른다. 서버 배포·Unity 플레이 검증은 수행하지 않았다.

## 방향

적 6장의 성장 상태를 각각 저작한다. 일반전은 조합의 핵심 카드부터 성장시키고, 티어 마지막 전투는 에이스 1~2장이 강화된 덱으로 구성한다. 실제 접속 시간이나 플레이어의 현재 덱 전투력에 비례해 적을 강화하지 않는다. 성장했을 때 기존 상대를 더 쉽게 이기는 체감을 보존한다.

적의 기준 성장량은 첫 1시간 가이드 목표에 맞춘다. 시간은 밸런스 검증용 기준이며 매칭 입력이 아니다. 모험·가이드에 쓰는 시간이 있으므로 60분 안에 특정 랭크에 도달한다고 가정하지 않는다.

적용 범위는 랭크 AI전. 모험은 정점별 난이도, 튜토리얼은 고정 연출, 실제 유저 대전은 상대 유저 성장값을 유지한다.

## 현재 확인한 기반

- `GUIDE_MISSIONS_FIRST_HOUR.md`의 목표는 약 20분 첫 시너지, 30분 두 조합, 40분 첫 3성, 55~60분 주력 3성 2장 + 2성 4장이다. 실측 성장 분포가 아니라 목표 배분이다. 문서의 옛 구현 상태·비용 주석은 현재 코드의 근거로 사용하지 않는다.
- 현재 `CardEnhance_sheet.csv`의 0→1성 / 1→2성 / 2→3성 비용은 조각 10 / 20 / 150이다. 표시 0~3성은 내부 레벨 1~4다.
- 시너지는 내부 레벨 3(2성)부터 해금되고, 키워드는 카드별 해금 레벨을 따른다. 레벨 상승을 단순 HP 배율로 취급하지 않는다.
- `AIDeck`에 티어별 덱 후보·가중치·공통 레벨 범위가 있다. 현재 저작값은 공통 레벨 1이다. `findAiMatch`가 덱·공통 레벨을 결정하여 매치에 저장한다.
- 랭크는 등급당 4단계, 단계당 40점, 승리 +10점이다. 등급 경계는 별도 승급전이다. 예: 브론즈는 259점에서 승급전, 승리하면 실버 진입점 260점이 된다. 따라서 모든 마지막 전투를 단순히 `다음 경계 - 10점`으로 판정하면 틀린다.

## 첫 1시간의 상대 성장 기준

아래는 같은 성장 시점의 플레이어가 상대할 일반전 난이도 후보다. 실제 랭크 도달 시각과 연결하는 시간 잠금은 없다. 랜덤 간식·과금 성장은 필수 전제로 삼지 않는다.

| 성장 기준 | 일반전 적 구성 예시 | 마지막 전투의 차이 |
|---|---|---|
| 0~15분 | 0성 중심, 1성 0~1장 | 에이스 1장만 1성 |
| 15~25분 | 1성 중심, 조합 핵심 2성 1~2장 | 핵심 카드 1장 추가 성장. 시너지 동시 해금 여부를 별도로 점검 |
| 25~40분 | 핵심 3장 2성, 나머지 1성 | 핵심 2성 1장 추가 또는 에이스 1장 3성 |
| 40~55분 | 2성 6장 또는 3성 1장 + 2성 5장 | 에이스 3성 1~2장 |
| 55~60분 | 3성 1장 + 2성 5장 | 3성 2장 + 2성 4장. 첫 시간의 종합 시험 |

3성 6장을 첫 시간의 필수 벽으로 두지 않는다. 한계돌파도 이 구간 필수 요구에서 제외한다. 첫 시간 목표 덱이 조합과 조작으로 승급전을 이길 수 있게 조정한다.

## 티어별 곡선 초안

성급 합계는 저작 분배량을 확인하는 값이다. 카드별 HP·키워드·시너지가 달라 같은 합계가 같은 전투력을 뜻하지 않는다. 모든 프로필은 별도 전투 검증을 거친다.

| 등급 | IV / III / II / I 일반전 성급 합계 초안 | 구성 의도 |
|---|---|---|
| 브론즈 | 0 / 1 / 2 / 4 | 미강화에서 일부 1성으로. 완성 시너지 없이 기본 전투 학습 |
| 실버 | 6 / 8 / 9 / 10 | 1성 6장에서 시작, 핵심 카드 3장을 먼저 2성으로 만들어 한 조합을 가동 |
| 골드 | 11 / 12 / 13 / 14 | 2성 덱 완성 후 에이스만 3성. I 단계는 첫 1시간 목표 덱과 같은 성장량 |
| 플래티넘 | 15 / 16 / 17 / 18 | 3성 3장부터 6장까지. 덱별 승리 조건이 명확하게 드러나는 구간 |
| 다이아몬드 | 18 / 18 / 18 / 18 | 3성 상한 유지. 한계돌파 합계 0 / 2 / 4 / 6으로 점진 상승 |

예: 실버 II 합계 9는 `[2,2,2,1,1,1]`, 골드 I 합계 14는 `[3,3,2,2,2,2]`다. 모두 표시 성급이다. 합계를 맞추려고 무작위 카드에 성급을 배분하지 않고 덱의 역할에 맞춰 고정한다.

브론즈→골드의 실제 소요 시간은 별도 측정한다. 첫 시간 목표 덱이 골드 I 수준이라는 뜻이지, 첫 시간에 골드 I 도달을 요구하는 설계가 아니다. 첫 시간에 도달하는 실제 티어가 너무 쉽거나 어렵다면 보상 속도·매치 수와 함께 곡선의 위치를 조정한다.

## 마지막 전투 규칙

세 종류를 둔다. 우선순위는 `등급 승급전 > 단계 마지막전 > 일반전`이다.

1. **일반전:** 현재 티어의 기본 성장 프로필. 같은 티어에서 매판 레벨을 무작위로 올리지 않는다.
2. **단계 마지막전:** 승리 정산을 미리 계산했을 때 다음 단계로 넘어가는 전투. 예: 브론즈 IV의 130점→140점. 에이스 1장에 +1성인 전용 프로필을 사용한다.
3. **등급 승급전:** 기존 정산의 `promoBattle` 조건을 그대로 공유한다. 예: 259점의 브론즈→실버 승급전. 에이스 1~2장에 합계 +2성 이내인 전용 프로필을 사용한다. 시너지 완성과 키워드 해금이 겹치면 +1성만 주는 등 예외를 저작한다.

보너스는 범용 런타임 덧셈이 아니라 프로필을 만드는 기준이다. 3성 상한에서 초과 레벨을 만들지 않는다. 상한에 도달한 프로필은 한계돌파 1~2단계 추가로 차이를 만든다. 다이아몬드 최종 단계처럼 다음 티어가 없는 경우 승급전을 만들지 않는다.

브론즈 I→실버 IV에서는 일반전 합계 4, 승급전 합계 6, 다음 티어 일반전 합계 6으로 자연스럽게 연결된다. 골드 I→플래티넘 IV에서는 14→최대 16→15로 작은 휴식 구간을 허용한다. 승급전에서 다음 티어 난이도를 먼저 경험하게 하는 구성이다.

패배 시 기존 점수 정산만 적용한다. 다음 상대를 패배 횟수만큼 더 강화하지 않는다. 다시 마지막전 조건을 충족하면 같은 난이도 프로필을 사용한다. 승리 전에 화면을 나가서 일반전 상대를 다시 뽑는 식의 우회는 허용하지 않는다.

## 카드별 역할과 표시

- 에이스: 주력 피해·핵심 키워드 카드. 먼저 성장시키고 대치 화면에서 강조한다.
- 조합 핵심: 시너지 요구 인원을 맞추는 카드. 2성 해금 순서를 덱 단위로 저작한다.
- 보조: 후방 지원·보완 카드. 에이스보다 성급을 낮춰 공략할 틈을 남긴다.
- 같은 티어의 후보 덱은 성장량뿐 아니라 상성 편차도 검사한다. 시너지가 작동하지 않는 미성숙 덱과 완성 덱을 같은 난이도 후보로 섞지 않는다.
- 대치 화면에 `승급전` 또는 `강적` 표시와 카드별 성급을 보여준다. 전투 중 숨은 HP·피해 배율은 넣지 않는다.

## 저작 데이터 제안

기존 `AIDeck`는 카드 구성·후보 가중치·티어 범위를 맡는다. 성장값과 마지막전 설정은 신규 서버 전용 표 `RankAiEncounter`로 분리한다. 다른 시스템이 쓰는 `RankGrade`에 성장 열을 추가하지 않는다.

한 행은 `tierIndex + battleKind + deckId`에 대응한다. 키가 중복되면 저작 오류다.

| 필드 | 의미 |
|---|---|
| id | 변경하지 않는 행 식별자 |
| tierIndex | 0~19, 등급별 4단계 |
| battleKind | Normal / DivisionFinal / GradeFinal |
| deckId | 기존 AIDeck의 덱 식별자 |
| level1~level6 | 해당 덱 card1~card6의 내부 레벨 1~4 |
| limitBreak1~limitBreak6 | 카드별 한계돌파 0~3 |
| highlightSlot | 대치 화면에서 강조할 에이스. 0=없음, 1~6=카드 슬롯 |

후보는 해당 티어·전투 종류의 성장 프로필이 존재하는 덱만 사용하고, 등장 가중치는 기존 AIDeck 값을 사용한다. 일반전과 마지막전 프로필 누락을 자동 레벨 보정으로 숨기지 않는다. 공개 전 전체 티어의 유효 후보와 카드 ID·레벨 범위를 검증한다.

성장 프로필에서 숫자를 고칠 때는 CSV만 수정한다. 정식 표 추가·생성 산출물 반영·업로드는 구현 단계의 별도 작업이다.

## 구현 연결과 결정론

1. `findAiMatch`가 서버 랭크 점수와 기존 승리 정산 규칙으로 전투 종류를 결정한다. 클라이언트가 승급전 여부나 적 레벨을 정하지 않는다.
2. 덱을 고른 직후 슬롯의 성장값을 카드 ID에 연결한다. 셔플 뒤 슬롯 번호로 적용하면 카드와 성장값이 바뀌므로 금지한다.
3. 매치 문서에 `battleKind`, 프로필 ID, 카드별 level/limitBreak, 실제 전투 스냅샷과 스펙 버전을 함께 고정한다. 같은 txId 재시도는 기존 결과를 반환한다. 서로 다른 txId로 진행 중 마지막전을 새로 뽑는 경로도 확인한다.
4. 서버 응답→대치 화면→실제 필드→덱 해시→`submitMatchResult`→재시뮬까지 같은 카드별 성장 스냅샷을 사용한다. 현재 공통 `cardLevel`을 읽는 `buildAiDeckSnapshots`와 클라이언트 성장 공급자를 함께 바꿔야 한다.
5. 한계돌파 HP는 플레이어와 같은 CardLimitBreak 규칙을 사용한다. 전투 시작 이후 바뀐 표로 진행 중 매치의 성장값을 재계산하지 않는다.
6. 기존 공통 레벨 매치의 결과 제출은 계속 읽을 수 있게 한다. 새 카드별 성장 계약을 지원하는 앱에만 새 매치를 발급한다. 세이브 v8은 변경할 이유가 없다.

## 확인할 결과

- 경계 테스트: 130점 단계 마지막전, 250점 일반전 승리 후 259점 정지, 259점 등급 승급전, 승급전 패배·재도전, 최고 티어.
- 각 프로필에서 같은 매치의 표시 성급·HP·키워드·시너지와 서버 재시뮬 결과가 일치한다. 카드 정렬·셔플·재접속에도 같다.
- 첫 시간 목표 덱은 일반전을 안정적으로 이기고 승급전에서 조합·조작 차이가 드러난다. 초기 플레이 테스트 목표는 일반전 승률 65~75%, 승급전 45~60%이며 보장값이 아니다.
- 시뮬레이션은 여러 덱·선후공·배치·시드를 비교하고, 플레이 테스트는 도달 티어·실제 성장·실패 후 재도전 시간을 함께 기록한다.
- 앞 티어 마지막전과 다음 티어 일반전 사이에 과도한 난이도 단절이 없다. 첫 시간에 만렙 6장·한계돌파·특정 랜덤 카드가 필수가 되지 않는다.

권장 구현 순서: 카드별 성장 전달 일치 → 브론즈·실버 프로필 및 마지막전 → 첫 시간 플레이 검증 → 골드 이상 확장. 숫자를 한 번에 확정하기보다 같은 전투 입력으로 비교할 수 있게 만든 뒤 보정한다.
