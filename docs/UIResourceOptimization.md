# UI·카드 리소스 최적화 (2026-09-14)

## 적용

| 항목 | 변경 |
|---|---|
| TMP 폰트 4개 | 4096² → 2048², 필요할 때 추가 페이지를 만드는 Dynamic Multi Atlas 활성화 |
| 폰트 데이터 | 현재 각 1페이지. Alpha8 아틀라스 합계 64 → 16MiB. 문자·글리프 픽셀·크기·자간·외곽선 유지 |
| 카드 아트 | 초기화는 주소만 확인. 실제 화면에서 비동기 로드하고 표시 중에는 참조 유지 |
| 카드 캐시 | 화면에서 사용하지 않는 완료 리소스는 최근 24장까지만 유지. 표시 중인 카드는 제한에서 제외 |
| 카드 뷰 | 전투·컬렉션·도감·팩 확률·획득 연출·덱 대표 이미지가 같은 참조 수명 관리 사용 |
| UI 프리팹 | 초기 선로드 28 → 21개. 선택형 화면 7개는 처음 열 때 비동기 적재 |
| 덱 컬렉션 | 전체 카드에는 빈 배치 슬롯만 유지. 실제 카드 타일은 화면과 여유 행만 생성·재사용 |
| 공용 아이콘 | 키워드·시너지 31개를 CardIcons.spriteatlas의 ASTC 6×6 한 페이지로 패킹 |
| 불필요한 복사 | UI 텍스처 2개의 Read/Write 해제 |
| VFX 중복 | 동일 파일·동일 Importer 15쌍의 재질 참조 통합. 원본 파일 보존 |
| 입력 검사 | CardView 장식 텍스트 5개의 Raycast Target 해제 |

지연 로드 UI: PackOddsPopup, SettingsPanel, LobbySettingPanel, MissionPanel, PassPanel,
RankingBoardPanel, RoulettePanel(주소 RouletteOverlay).
동기 반환값이 필요한 팝업·입력 차단·전투 UI는 선로드를 유지한다.

처음 UI를 열 때 로드를 기다리는 동안 입력을 차단한다. 호출 화면이 닫히거나 요청이 취소되면
늦게 도착한 프리팹을 표시하지 않는다. 실패 시 안내하고 다음 요청에서 재시도한다.

카드 원격 번들의 초기 다운로드 정책과 디스크 캐시는 기존 Firebase 리소스 흐름을 따른다.
이번 카드 변경은 모든 진화 아트의 메모리 선적재를 제거한다. 다운로드 용량 감소 수치가 아니다.
공유 폰트·아이콘 중복을 피하기 위해 UI 번들의 Pack Together는 유지한다.

## 확인 범위

- Unity 프로젝트 컴파일 확인.
- 폰트의 기존 Unicode 매핑, glyph metrics, feature table, glyph 픽셀 데이터 비교 통과.
- 아이콘 31개 실제 패킹, 통합한 VFX 텍스처 참조 로딩 확인.
- 카드 32장 실제 Addressables 적재에서 공유 요청·표시 중 참조 유지·24장 캐시 상한·재바인딩 확인.
- 타일 공개 API: 이전 클릭 자격 해제, 장착 중 입력 차단, 마우스 버튼 구분, 재바인딩 시 확대 복원 확인.
- 덱 목록 0~1000장 배치 범위 계산 검증. 예시 850px 뷰포트에서는 최대 18개 카드 타일.

실제 기기의 FPS, Canvas rebuild, GPU 메모리, 드로콜은 아직 측정하지 않았다.
대량 목록의 실제 플레이 검증은 미실행이다. 자동 승인 검토가 테스트용 내부 상태 주입의
System.Reflection 사용을 거절하여 공개 API 검증과 계산 검증으로 범위를 제한했다.
비동기 UI 첫 열기의 전체 플레이 흐름과 화면 전환도 기기 확인이 필요하다.
편집 모드에서 카드 테스트를 반복 실행한 경우 Addressables 카탈로그 완료 대기에서 시간 초과가 발생했다.
첫 실행의 리소스 검증과 구분하며, 플레이 모드 수명 검증 통과로 보지 않는다.
UI 로딩의 동적 테스트 스크립트는 MCP 컴파일러의 UniTask 참조 누락으로 실행되지 않았다.

폰트 백업은 `Build/OptimizationBackups/20260914-062637/`에 있다.
기존 VFX에서 발견한 별도 누락 참조와 카드 프리팹의 기본 아트 직접 참조는 이번 변경에서 유지했다.
