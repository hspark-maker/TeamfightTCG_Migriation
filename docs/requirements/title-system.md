# 칭호 시스템

2026-09-21 사용자 확정. 꾸미기 전용, 네 가지 획득 경로와 초기 12종을 포함한다. 이 문서는 신규 개발 요구사항이며 구현 완료 보고가 아니다.

## Overview

플레이 성취로 칭호를 영구 획득하고 하나를 장착해 개성을 표현한다. 기존 프로필 편집에서 선택하며 로비·매칭 화면의 닉네임 주변에 표시한다. 매칭 상대에게도 장착 칭호를 보여준다.

## Goals

- 계정 레벨·랭크 도달·모험 클리어·도감 완성으로 칭호를 획득한다.
- 칭호 목록에서 보유 여부, 획득 조건과 진행도를 확인한다.
- 보유 칭호 하나를 직접 장착하거나 해제한다.
- 재접속 후에도 보유·장착 상태를 유지한다.
- 기존 계정에도 저장된 달성 기록에 근거해 소급 지급한다.

초기 칭호 12종:

| 획득 경로 | 칭호 | 획득 조건 |
|---|---|---|
| 계정 레벨 | 첫 발걸음 | 계정 레벨 5 달성 |
| 계정 레벨 | 익숙한 발걸음 | 계정 레벨 10 달성 |
| 계정 레벨 | 오래된 발자취 | 계정 레벨 20 달성 |
| 랭크 | 승부의 시작 | 브론즈 최초 도달 |
| 랭크 | 빛나는 승부사 | 실버 최초 도달 |
| 랭크 | 황금의 도전자 | 골드 최초 도달 |
| 모험 | 문밖의 세계 | 첫 챕터 전체 클리어 |
| 모험 | 길을 여는 자 | 두 번째 챕터 전체 클리어 |
| 모험 | 끝없는 여정 | 네 번째 챕터 전체 클리어 |
| 도감 | 첫 수집 | 도감 페이지 1개 완성 |
| 도감 | 수집의 즐거움 | 도감 페이지 3개 완성 |
| 도감 | 작은 박물관 | 도감 테마 1개 완성 |

공통 규칙:

- 조건 달성 시 별도 수령 조작 없이 자동 획득한다. 기존 장착을 자동 교체하지 않는다.
- 한 번 획득하면 영구 보유한다. 랭크 하락으로 회수하지 않는다.
- 미획득 칭호도 목록에 공개하며 선택하면 조건과 진행도를 보여준다.
- 별도 희귀도 없이 획득 경로별 문양으로 구분한다.
- 칭호 이름은 닉네임보다 작게 표시한다.

## Out of Scope

- 전투 능력치·재화 획득량 보너스.
- 칭호 강화·합성·거래·유료 구매.
- 기간제·시즌 만료 칭호.
- 사용자가 직접 입력하는 칭호.
- 기존 프로필·로비 화면의 전면 재설계.

## Technical Requirements

- 기존 `ProfileManager`, `ProfileEditPanel`, `ProfileSaveData`의 프로필 흐름을 활용한다. 현재 프로필 편집은 저장·닫기·외부 숨김 때 변경을 확정하며 칭호도 같은 조작 규칙을 따른다.
- 칭호 정의는 안정적인 ID로 식별한다. 이름·조건 등 기획값의 저장소 진실원은 스펙 CSV로 두고 그림·색 등 표현 자원을 연결한다. 구체적인 클래스 구성·스키마는 구현 단계에서 정한다.
- 서버가 조건을 검증하고 획득을 확정한다. 클라이언트의 보유 상태는 서버 확정값을 따른다. 재접속·재요청에도 중복 지급되지 않아야 한다.
- 장착은 미장착 또는 보유 칭호 하나만 허용한다. 미보유 ID의 장착을 거절하며 저장 실패를 성공으로 표시하지 않는다.
- 장착 상태를 프로필 저장 및 매칭 전달에 연결한다. `MatchmakingProfile`, `MatchProfile`, `MatchProfileView`의 기존 전달·표시 흐름을 참고한다.
- 칭호 없는 기존 계정·상대는 칭호 영역을 숨긴다. 알 수 없는 ID도 화면 표시나 매칭 진입을 막지 않는다.
- 잠금은 자물쇠·흑백, 선택은 테두리·체크로 구분한다. 조건 설명과 진행도는 선택한 칭호의 상세 영역에 둔다. 색만으로 상태를 구분하지 않는다.
- 도감 완성은 기존 완성 판정과 일치시킨다. 준비 중 테마와 빈 페이지·빈 테마를 완성으로 세지 않는다. 완성 페이지는 테마와 페이지 식별자 조합으로 중복 없이 집계하며 보상 수령 여부와 구분한다.
- 모험 챕터 전체 클리어는 해당 챕터의 모든 정점 클리어를 뜻한다. 표시 순번 대신 안정적인 챕터 식별자에 연결한다.
- 조건 평가와 기존 계정 소급 지급 모두 서버에서 확인 가능한 기록을 사용한다. 기록이 없는 과거 성취를 추측해 지급하지 않는다.
- 정식 시트 스키마 추가·생성 산출물 갱신은 별도 명시적 지시 범위에서 진행한다. `SpecData.bytes`를 에이전트가 수정·생성하거나 임포터로 재생성하지 않으며 자동 생성 C# 파일도 수동 수정하지 않는다. 문서 확정 자체를 배포·산출물 갱신 승인으로 해석하지 않는다.

현재 저장소 확인 및 구현 시 주의점:

- `AccountLevel_sheet.csv`는 레벨 50까지 있어 초기 조건 5·10·20이 범위 안에 있다.
- `RankGrade_sheet.csv`에 Bronze·Silver·Gold가 존재한다.
- `AdventureChapter_sheet.csv`에 `chapter_01`~`chapter_04`가 존재한다. 초기 조건은 각각 `chapter_01`, `chapter_02`, `chapter_04`에 해당한다.
- `AlbumThemeInfo_sheet.csv`에서 현재 열린 테마는 `Theme_Nature`이고 나머지 두 테마는 준비 중이다. 페이지 3개 완성 조건의 도달 가능성을 실제 공개 페이지 구성과 함께 검증한다.
- `RankSaveData`는 현재 점수와 수령한 티어 목록을 가지며 최고 도달 랭크 전용 필드는 없다. 도입 전 랭크 하락 계정의 과거 성취를 전부 복원할 수 있다고 가정하면 안 된다. 서버의 보상 기록 등 신뢰 가능한 근거를 조사하고, 복원할 수 없는 범위를 구현 보고에 명시한다.
- 새 스펙 표 도입은 시트·생성 코드·초기화 필수 표·서버 데이터 제공 경로를 함께 검토한다. 로컬 표만 추가해 기존 계정의 초기화를 막지 않아야 한다.

## Acceptance Criteria

- [ ] 확정된 12종이 네 가지 경로별로 목록에 표시된다.
- [ ] 보유·미보유·선택·장착 상태가 구분되고 미획득 조건과 진행도를 확인할 수 있다.
- [ ] 각 조건의 미달·달성 경계에서 서버 획득 판정이 정확하다.
- [ ] 조건 충족 시 자동 획득하며 기존 장착을 바꾸지 않는다.
- [ ] 동일 조건 재평가·재요청·재접속으로 중복 지급되지 않는다.
- [ ] 보유 칭호 하나만 장착할 수 있고 미장착으로 해제할 수 있다.
- [ ] 프로필 편집 종료 규칙이 기존 아바타·프레임 편집과 일치한다.
- [ ] 재접속 후 보유·장착 상태가 복원된다.
- [ ] 랭크 하락 후에도 이미 획득한 칭호가 유지된다.
- [ ] 기존 계정에 확인 가능한 달성 기록으로 소급 지급되며 확인 불가능한 기록을 추측하지 않는다.
- [ ] 도감 페이지·테마 완성과 모험 챕터 전체 클리어가 기존 콘텐츠 판정과 일치한다.
- [ ] 로비·매칭에 동일한 장착 칭호가 표시되고 상대 칭호도 전달된다.
- [ ] 칭호 정보 없는 기존 계정·상대와 알 수 없는 ID가 정상 처리된다.
- [ ] 미보유 칭호 장착을 거절하고 저장 실패를 성공으로 표시하지 않는다.
- [ ] 칭호가 닉네임을 가리거나 잘리지 않으며 작은 화면에서도 상태와 이름을 읽을 수 있다.
- [ ] 칭호 도입으로 기존 프로필 편집·계정 초기화·매칭이 회귀하지 않는다.
- [ ] 전투 능력치와 재화 획득량에 영향을 주지 않는다.

## Open Questions

기획 미결 사항 없음. 꾸미기 전용·네 가지 획득 경로·초기 12종·공통 규칙 모두 사용자 확정.

구현 전 검증 사항은 과거 랭크 성취의 서버 근거와 복원 범위, 공개 도감 페이지 구성에 따른 3페이지 완성 조건의 도달 가능성이다. 확인 결과 조건 변경이 필요하면 확정값을 임의 변경하지 않고 별도 논의한다.
