# FTUE 이후 가이드 미션 중심 성장 유도 PRD

## Overview

### 문서 목적과 상태

- 작성일: 2026-09-15.
- 목적: 이번 세션에서 수행한 FTUE·자율 온보딩·가이드 미션 진단과 재설계 제안을 상세히 기록한다.
- 작성 형식: 저장소 PRD 스킬 명세의 Overview → Goals → Out of Scope → Technical Requirements → Acceptance Criteria → Open Questions 순서를 따른다.
- 상태: 진단 및 요구사항 제안. 문서 저장은 요청받았으며, 아래 재설계의 구현·밸런스 변경·서버 배포가 완료되거나 승인되었다는 의미는 아니다.
- 근거: 현재 저장소 코드·튜토리얼 에셋·스펙 CSV의 읽기 전용 조사와 공개된 상용 게임 자료. 조사 시점 HEAD는 `d93de9cad`다.
- 한계: 플레이 모드 실측, 실제 서버 배포값 확인, 신규 유저 사용성 테스트, 리텐션 분석은 수행하지 않았다. 코드에서 확인한 사실과 경험에 대한 추론을 구분한다.

### 사용자 의도

초반 FTUE 이후에는 가이드 미션을 중심으로 카드 진화·시너지 등 아웃게임 콘텐츠를 강제 없이 전개한다. 현재 자율 온보딩의 역할이 애매하므로, 상용 게임 패턴과 현 구현을 비교해 FTUE와 이후 경험의 분리 기준을 정한다.

여기서 자유는 입력을 막지 않는 것에 그치지 않는다. 플레이어가 성장 대상과 행동 시점을 선택하고, 안내를 중단하거나 다른 콘텐츠를 먼저 즐겨도 진행 방법을 잃지 않는 상태를 뜻한다.

### 핵심 제안

**FTUE는 최소 조작 학습을 끝내고 졸업한다. 이후에는 가이드 미션이 성장 목표를 제시하고, 맥락 도움말이 필요한 방법만 설명한다. 기능 해금은 이용 자격을 별도로 판정한다.**

현재 자율 온보딩이 가진 긴 진행 시퀀스를 계속 확장하기보다, 해당 화면에서 끝나는 짧은 도움말로 역할을 축소한다. FTUE와 이후 경험의 저작·진행 책임은 분리하되, 강조·앵커·데모·표시 충돌 조정 같은 공용 부품은 재사용한다.

권장 경험은 다음과 같다.

**FTUE 졸업 → 가이드 미션에서 목표 확인 → 목적지 이동 → 필요한 도움말 → 직접 성장·편성 → 결과와 효과 확인 → 다음 목표 선택**

### 현재 책임이 겹치는 지점

| 영역 | 현재 결정하는 것 | 충돌 가능성 |
|---|---|---|
| 가이드 미션 | 성장 대상, 달성 조건, 추천 순서, 보상 | 플레이어가 다른 카드를 성장시키면 현재 목표와 보상이 정체됨 |
| 자율 챕터 | 클릭 순서, 설명 확인, 화면 닫기, 안내 완료 | 자유 탐색 중 진입한 화면에서 긴 조작 시퀀스가 시작됨 |
| 시너지 소개 | 설명 시작 시점, 대상 덱, 소개 완료 순서 | 성장 미션을 달성해도 실제 활성 덱이 없으면 소개가 시작되지 않음 |
| 기능 해금·소개 | 이용 자격과 새 콘텐츠 알림 | 다른 안내와 표시 시점이 경쟁하며 관련 상태를 서로 기다림 |

문제의 중심은 파일 개수가 아니라 FTUE 이후 진행의 주도권이 여러 시스템에 분산된 점이다. 에셋을 두 개로 나누는 것만으로는 해결되지 않는다.

### 현 시스템 진단

#### D1. 자율성은 시작 시점에만 적용되는 경향이 있다

현재 `OutgameTutorial.asset`은 선두 강제 4챕터와 후속 자율 4챕터를 함께 저작한다. 자율에는 카드 강화, 키워드 강화, 모험 소개, 미션·룰렛·카드 강화 해금 소개가 포함된다.

- 카드 강화는 7스텝이다. 카드 선택과 강화에 이어 해금 설명, 카드 상세 닫기, 도감 페이지 닫기, 마무리 설명이 연결된다.
- 키워드 강화는 4스텝이며 지정 키워드 강화와 결과 설명으로 이어진다.
- 모험 소개는 8스텝이며 해금 소개부터 덱 화면 설명과 전투 시작까지 연결된다.
- 자율 챕터도 FTUE와 동일한 게이트를 사용한다.
- `ShowGate`는 딤 설정에 따라 입력을 차단하며, `ShowMessageGate`는 딤이 꺼져도 확인 탭을 받기 위해 입력을 차단한다.

경험상 위험: 플레이어가 카드를 구경하거나 특정 메뉴를 확인하려고 진입했는데 시스템이 정한 교육 순서가 시작될 수 있다. 시작이 자발적이어도 진행 중 선택권은 제한된다.

#### D3. 성장 완료와 시너지 편성 학습 사이에 빈 구간이 있다

`guide.06`은 지정 3종을 2성 이상으로 보유하면 완료된다. 덱 편성을 요구하지 않는다. 이후 `guide.07`은 모험 정점 클리어만 판정한다.

반면 돌보미 소개 후보가 되려면 해당 성장 미션을 달성하고 실제 돌보미 활성 덱도 존재해야 한다. 카드를 키웠지만 편성하지 않은 플레이어는 설명을 받기 위해 먼저 편성을 스스로 성공해야 하는 상황에 놓일 수 있다.

추적 소개는 돌보미 소개 완료 이후에만 선택된다. 다른 조합을 먼저 탐색한 플레이어도 앞선 소개 순서의 영향을 받는다.

필요한 연결은 다음 세 상태의 구분이다.

1. **해금:** 카드 성장으로 시너지에 참여할 자격이 생겼다.
2. **준비:** 조합에 필요한 카드와 성장 조건을 갖췄다.
3. **활성:** 실제 덱 편성이 효과 발동 조건을 충족했다.

성장 완료 시에는 준비 상태와 편성 방법을 제시하고, 실제 활성 후에는 켜진 효과를 확인해야 한다. 준비 완료를 활성화 완료로 표현하거나, 활성화 전에는 방법을 설명하지 않는 구조를 피한다.

#### D4. 미션 이동이 실제 목표와 다른 카드 강화를 안내할 수 있다

강화 안내는 현재 미션의 대상 카드를 우선 선택하지만, 해당 후보가 강화 불가능하면 전체 보유 카드 중 강화 가능한 카드로 대체한다. 후보 판정에는 소유, 다음 성장 단계, 열린 도감, 비용 조건이 포함된다.

이 경로는 안내 정지를 피할 수 있으나, 특정 카드 성장 미션에서 이동한 플레이어에게는 문제가 된다. 안내한 다른 카드에 자원을 써도 원래 미션은 진행되지 않을 수 있다.

목표를 달성할 대상이 준비되지 않았다면 부족 원인과 해결 경로를 알려야 한다. 단순 조작 연습과 미션 달성 안내를 같은 행동처럼 보여주지 않는다.

근거: [OutgameTutorialGuide.cs](../../Assets/Scripts/OutGame/Tutorial/OutgameTutorialGuide.cs)의 `PrepareEnhanceCard`, `CanGuideEnhance`, [GuideMissionNavigator.cs](../../Assets/Scripts/UI/Mission/GuideMissionNavigator.cs).

#### D5. 안내 완주와 실제 학습 상태가 어긋난다

자율 진행 커서는 메모리에 있고, 완주 시 트리거 완료 기록을 저장한다. 중간 이탈은 세션 미루기로 처리하며 다시 시작하면 첫 스텝에서 출발한다.

플레이어가 실제 강화를 성공한 뒤 후속 설명을 닫았다면, 성장 행동은 끝났지만 안내는 미완료로 남을 수 있다. 이런 상태에 긴 시퀀스 재생을 요구하면 이미 아는 조작을 반복하게 된다.

또한 첫 무료 강화 여부는 현재 안내 스텝, 무료 저작값, 서버 소진 표식과 연결돼 있다. 도움말을 보는 순서가 성장 비용 규칙에 관여하므로, 안내 역할을 줄일 때 혜택 자격과 함께 검토해야 한다.

근거: [OutgameTutorialRunner.cs](../../Assets/Scripts/OutGame/Tutorial/OutgameTutorialRunner.cs)의 `Fire`, `AbortGuided`, `FinishGuided`, [OutgameTutorialGuide.cs](../../Assets/Scripts/OutGame/Tutorial/OutgameTutorialGuide.cs)의 `HasFreeShot`.

#### D6. 표시 조정과 콘텐츠 진행 정책이 한곳에 섞여 있다

`GuidanceCoordinator`는 화면이 바쁜지 확인하는 것 외에도 미션 소개 요청, 강화 안내 재요청, 해금 소개 우선순위, 보류된 안내 재시도, 소유 카드 소개와 시너지 소개 연결을 처리한다.

표시 충돌을 한곳에서 조정하는 것은 유지할 가치가 있다. 다만 조정기가 무엇을 배울지와 어떤 목표를 수행할지까지 결정하면 새 콘텐츠마다 분기와 예외가 늘어난다.

목표 선택은 미션이, 도움말 내용은 해당 기능이, 표시 가능 여부는 공용 조정이 담당하도록 경계를 명확히 한다. 실제 클래스 분할 방식은 구현 단계에서 결정한다.

근거: [GuidanceCoordinator.cs](../../Assets/Scripts/UI/Tutorial/GuidanceCoordinator.cs)의 `RequestMissionEnhance`, `TryFire`, `ResumePendingGuide`, `Update`.

#### 현재 문제로 단정하지 않을 사항

- 필수 카드 지급이 전혀 없다는 과거 진단은 현재 저장소에 그대로 적용하지 않는다. FTUE 지급 경로와 `guide.07` 버섯냥 보상, 서버의 보상 지급 처리가 존재한다.
- [Reward_sheet.csv](../SpecData/Reward_sheet.csv)와 [claimMission.ts](../../functions/src/commands/claimMission.ts)의 현재 내용을 근거로 하며, 오래된 메모나 CSV 설명의 “구현 대기” 문구만으로 미구현을 단정하지 않는다.
- 다른 카드 성장에 자원을 사용하면 지정 성장 코스가 늦어질 수 있다. 다만 전체 경제와 실계정 경로를 검증하지 않았으므로 재화 부족에 의한 영구 진행 불가로 단정하지 않는다.
- 코드상 가능한 충돌·반복·안내 누락과 실제 신규 유저의 발생 빈도는 구분한다.

## Goals

- FTUE 졸업을 명확히 하고 이후에는 플레이어가 행동을 선택하게 한다.
- 가이드 미션을 다음 성장 목표를 확인하는 중심 화면으로 만든다.
- 카드 성장 → 새 능력 해금 → 조합 준비 → 덱 활성 → 실전 체험을 이해할 수 있게 연결한다.
- 미션 이동이 현재 목표에 유효한 카드·화면·행동을 안내하게 한다.
- 설명을 닫거나 생략해도 게임 진행과 이미 얻은 성과를 유지한다.
- 준비 부족을 미보유·성장 부족·재화 부족·미편성으로 구분해 다음 행동을 알려준다.
- 이미 달성한 행동과 이해한 조작의 반복을 줄이고, 설명은 다시 열어볼 수 있게 한다.
- 신규 콘텐츠를 추가할 때 FTUE 전체 시퀀스를 확장할 필요가 없도록 책임을 분리한다.

성공은 안내 완주율만으로 판단하지 않는다. 안내 없이 자발적으로 성장·편성·실전 활용을 반복하는지까지 확인한다.

## Out of Scope

- 이번 문서 작성에서 코드·프리팹·튜토리얼 에셋·CSV를 변경하는 작업.
- 서버 배포, 실제 시트 업로드, 자동 생성 코드 갱신, `SpecData.bytes` 수정·재생성.
- 전투 FTUE의 세부 시나리오와 전투 규칙 전면 개편.
- 카드 성장 비용·시너지 수치·모험 난이도의 수치 확정.
- 미션 트래커·카드 상세·덱 편집 화면의 전면 시각 디자인 변경.
- 신규 범용 퀘스트 엔진이나 범용 튜토리얼 프레임워크 제작.
- 일일·주간 미션과 모든 이벤트 콘텐츠의 구조 통합.
- 기존 문서나 팀 공유 지침의 수정·정리.

## Technical Requirements

아래 항목은 목표 동작에 대한 제안 요구사항이다. 클래스명·메서드 시그니처·서버 스키마의 신설 방식은 확정하지 않는다. 기존 타입은 구현 참고 지점으로만 명시한다.

### TR-01. 시스템별 책임

| 영역 | 소유할 책임 | 경계 |
|---|---|---|
| FTUE | 최소 조작 학습, 강제 진행, 재접속 복원, 졸업 | 후속 콘텐츠 학습 완료를 졸업 조건에 추가하지 않는다 |
| 가이드 미션 | 목표, 달성, 보상, 추천, 이동 목적 | 설명 시청을 달성 조건으로 삼지 않는다 |
| 맥락 도움말 | 현재 화면의 방법·조건·효과 설명, 선택적 시범 | 사용자 대신 성장·편성·전투 진입을 실행하지 않는다 |
| 기능 해금 | 콘텐츠 이용 자격 | 해금 알림을 닫거나 보지 않았다는 이유로 이용을 막지 않는다 |
| 공용 표시 조정 | 동시 노출 방지, 화면 유효성, 표시 우선순위 | 목표 순서와 보상 지급 조건을 소유하지 않는다 |

FTUE와 후속 도움말은 저작과 진행 상태의 책임을 분리한다. 공통 실행 부품이나 표시기를 공유하는 것은 가능하다. 별도 러너 두 개를 반드시 만드는 방식이나 현재 러너를 반드시 유지하는 방식으로 구현을 고정하지 않는다.

### TR-02. FTUE 졸업 이후 첫 경험

- 기존 FTUE 졸업 시점에 도달하면 자유 플레이가 가능해야 한다.
- 가이드 미션의 위치와 역할을 짧게 알린다. 소개를 닫아도 미션은 지속적으로 찾을 수 있어야 한다.
- 졸업 직후 해금 소개·강화 안내·시너지 안내를 긴 연속 시퀀스로 몰아서 재생하지 않는다.
- 홈의 현재 목표는 무엇을 하면 되는지와 예상 보상을 이해할 수 있어야 한다.
- 목표 추천 변경 때문에 이미 달성한 진행도가 사라지지 않는다.

### TR-03. 미션 이동의 의미

- “이동”은 해당 목표를 진행할 수 있는 화면으로 안내한다.
- 카드가 지정된 미션은 그 대상과 미달성 조건을 유지한다.
- 강화 가능한 무관한 카드로 조용히 바꾸지 않는다.
- 유효 후보가 여러 개면 목표에 기여하는 후보 중에서 선택하게 한다.
- 목표가 이미 달성됐으면 불필요한 재행동 대신 달성 상태·보상·다음 행동을 보여준다.
- 목적지 도착 후 플레이어가 다른 탭이나 화면을 선택하면 이전 안내 요청을 취소한다.
- 목적지 이동만으로 재화를 소모하거나 덱을 저장하거나 전투를 시작하지 않는다.

### TR-04. 준비 부족 상태

| 상태 | 보여줄 정보 | 다음 행동 |
|---|---|---|
| 카드 미보유 | 필요한 카드와 미보유 상태 | 확인된 획득 경로 또는 다른 가능한 목표 |
| 성장 부족 | 현재 성급과 목표 성급 | 해당 카드 성장 화면 |
| 재화 부족 | 필요한 비용과 부족량 | 실제 이용 가능한 수급 콘텐츠 |
| 조합 준비 완료·미편성 | 필요한 카드 준비 완료, 같은 덱 편성 필요 | 덱 편집으로 이동 |
| 시너지 활성 | 참여 카드와 활성 효과 | 효과 확인 또는 실전 활용 |
| 이미 학습·달성 | 현재 충족 상태 | 반복 생략, 도움말 재열람 제공 |

재화·소유·성장 정보는 기존 도메인과 서버 응답에서 가져온다. 도움말이 별도 비용 상수나 별도 보유 상태를 만들지 않는다. 이용 불가능한 수급 경로를 해결책으로 표시하지 않는다.

### TR-05. 카드 성장과 진화 안내

- 미션 문구는 현재 실제 판정과 일치해야 한다. 현재 첫 진화 성격의 `guide.05`는 보유 카드 1장 2성 도달이며, 임의의 “진화 버튼 1회 클릭”으로 해석하지 않는다.
- 첫 조작 안내는 카드 상세 안에서 끝나도록 축소한다.
- 짧은 설명으로 부족할 때 플레이어가 시범이나 자세한 도움말을 요청할 수 있다.
- 성장 결과로 새 능력이 열리면 무엇이 달라졌는지 해당 카드와 연결해 보여준다.
- 결과 설명이 끝났다는 이유로 카드 상세나 도감 페이지를 자동으로 닫지 않는다.
- 사용자가 계속 성장하거나 다른 카드를 살펴볼 수 있어야 한다.
- 실제 성장 완료가 확인된 계정에 조작 학습을 이유로 같은 소비를 반복 요구하지 않는다.

### TR-06. 시너지 해금·준비·활성의 연결

- 첫 해금에서는 성장한 카드가 실제로 획득한 시너지를 설명한다.
- 아직 덱 조건을 충족하지 않았다면 “해금”과 “활성”을 구분한다.
- 조합 준비 완료 시점에는 활성 덱이 없어도 편성 방법을 확인할 수 있어야 한다.
- 준비된 카드와 부족한 조건을 같은 문맥에서 보여준다.
- 덱 편집에서는 실제 참여 카드·장수·현재 충족 상태를 표시한다.
- 실제 활성 후에는 켜진 효과를 확인한다. 이미 활성화된 계정에 카드를 뺐다가 다시 넣도록 요구하지 않는다.
- 다른 시너지 설명을 완료하지 않았어도 현재 보고 있는 시너지의 조건·효과 도움말은 열람 가능해야 한다.
- 실전 활용을 권장하는 것과 실제 전투에서 그 덱 사용을 달성 조건으로 검사하는 것은 구분한다.
- 현재 모험 정점 클리어 미션에 안내 구현만으로 시너지 덱 사용 조건을 추가하지 않는다.

### TR-07. 권장 사용자 여정

| 단계 | 플레이어 목표 | 시스템 지원 | 종료 조건 |
|---|---|---|---|
| 1. 졸업 | 자유롭게 다음 행동 선택 | 가이드 미션 위치 소개 | 소개를 닫아도 자유 플레이 유지 |
| 2. 첫 성장 목표 | 내 카드 성장 | 유효 대상 표시·이동 | 실제 성장 반영 |
| 3. 방법 확인 | 강화 방법 이해 | 짧은 화면 내 안내 | 이해했으면 즉시 닫기 가능 |
| 4. 새 능력 확인 | 성장 이유 이해 | 실제 해금 효과와 선택적 데모 | 카드 화면에 머무를 수 있음 |
| 5. 조합 준비 | 함께 쓸 카드 파악 | 보유·성장·편성 부족 상태 | 다음 행동을 스스로 선택 |
| 6. 덱 활성 | 시너지 켜기 | 참여 카드와 활성 조건 표시 | 실제 유효 덱 상태 확인 |
| 7. 실전 체험 | 성장·편성 결과 활용 | 관련 모험·전투 목표 추천 | 직접 전투를 선택 |
| 8. 후속 탐색 | 다른 성장 방식 시도 | 다음 목표·다른 목표·도움말 | 고정 안내 커서 없이 진행 |

### TR-08. 미션 자유도

권장 방향은 입문 경험에 필요한 순서만 유지하고, 이후에는 목표 선택 폭을 넓히는 것이다.

- 첫 시너지까지 돌보미를 고정하는 방식을 택한다면, 필요한 카드·재화 확보와 편성까지를 짧고 완결된 입문 과제로 구성한다.
- 특정 카드의 선호를 강요하지 않는 방식이라면, 실제 소유와 성장 상태에 맞는 조합을 추천한다.
- 첫 시너지 이후에는 “지정 카드 조합 재현”에서 “시너지 활성”, “주력 카드 성장” 같은 결과 중심 목표로 확대하는 방향을 검토한다.
- 현재 추천 목표를 미뤄도 이미 달성한 다른 목표가 보이지 않게 되지 않아야 한다.
- 추천 목표 선택과 보상 수령 순서는 서로 다른 정책이다. 추천을 바꿀 수 있다는 이유만으로 순차 보상 제한이 사라졌다고 간주하지 않는다.
- 미션 순서·대상·수령 정책 변경은 재화 선지급과 필수 카드 확보 경로에 영향을 주므로 함께 검토한다.

첫 시너지 고정 여부, 대체 목표 수, 수령 순서 완화 범위는 Open Questions에서 결정한다. 위 항목은 현재 CSV를 즉시 바꾸라는 지시가 아니다.

### TR-09. 도움말의 시작·중단·재열람

- 단순 첫 화면 방문만으로 긴 조작 시퀀스를 시작하지 않는다.
- 최초 짧은 힌트, 명시적 도움말 요청, 실제 해금 결과 확인을 구분한다.
- 일반 후속 도움말은 닫거나 무시할 수 있어야 한다.
- 플레이어가 명시적으로 선택한 시범에서 일시적 입력 제한이 필요하면 종료 경로를 제공한다.
- 딤이 없는 상태에서 이유를 알 수 없는 투명 입력 차단을 남기지 않는다.
- 화면 이탈 시 강조·입력 차단·보류 요청을 정리한다.
- 같은 세션의 “나중에” 선택을 단순 상태 갱신마다 취소하지 않는다.
- 다음 접속 때 미완료 도움말을 일괄 자동 재생하지 않는다.
- 실제 행동 상태를 기준으로 이미 학습한 조작은 생략하고, 도움말 재열람은 별도로 제공한다.
- 도움말 완료는 전체 게임 진행을 소유하는 또 하나의 긴 커서가 되지 않아야 한다.

### TR-10. 첫 성장 혜택과 서버 권한

- 첫 성장 혜택을 유지한다면, 특정 도움말 스텝에 서 있는지와 혜택 자격을 분리하는 방향으로 변경한다.
- 혜택 자격·소진의 권한은 서버에 유지한다.
- 도움말을 닫거나 보지 않았다는 이유만으로 혜택을 잃지 않게 한다.
- 서버 성공 후 응답 유실·재접속이 발생해도 혜택 중복 지급과 같은 행동의 재소비를 막는다.
- 도움말을 열었다는 사실만으로 혜택을 지급하거나 성장 완료를 확정하지 않는다.
- 무료 1회 유지, 다른 형태의 지원, 기존 소진 기록 연결 방식은 구현 전 결정한다.

### TR-11. 저장·기존 계정·동시 연출

- 미션 달성·보상 수령·기능 해금·도움말 표시 이력을 서로 다른 의미로 다룬다.
- 도움말 이력 초기화가 보상 재수령이나 성장 재지급으로 연결되지 않는다.
- 실제 소유·성장·덱 상태와 미션 서버 판정을 우선하며, 화면 연출 완료만으로 도메인 상태를 만들지 않는다.
- 기존 자율 챕터 완료 기록과 진행 중 계정의 전환 정책을 정의한다.
- FTUE 저장 좌표와 졸업 판정은 후속 도움말 분리 때문에 바뀌지 않아야 한다.
- 불가피하게 저장 구조를 바꾸면 읽기·쓰기·서버 채택 경로까지 검토한다.
- 보상, 성장 의식, 씬 전환, 콘텐츠 소개가 겹칠 때 한 번에 이해할 수 있는 피드백만 표시한다.
- 보류된 안내는 원래 화면과 대상이 아직 유효한 경우에만 재개한다.
- 공용 표시 부품을 쓰더라도 후속 도움말 정지가 FTUE 또는 기능 이용을 막지 않아야 한다.

### TR-13. 작업 순서와 세션별 태스크

2026-09-15 사용자 지시로 아래 착수 순서를 문서에 반영했다. 순서의 확정과 Open Questions의 미결 정책 확정은 구분한다. 아래 체크는 구현·검증 완료 상태이며, 이번 문서 갱신으로 완료 처리하지 않는다.

**착수 순서: 1단계(01~04) → 2단계(05~08) → 3단계(09~12) → 4단계(13~15) → 5단계 최종 검증(16~17).**

첫 작업 묶음은 **미션 이동 대상 일치 + 준비 부족 표시 + 돌보미 성장에서 편성 안내 연결**이다. 미션 자유도 정책 변경 전에 현재 목표와 안내의 불일치를 먼저 해소한다. 정책 검토와 측정 준비는 앞 단계부터 병행하고, 각 변경의 검증도 해당 단계에서 수행한다.

#### 1단계. 미션과 실제 행동 연결

- [ ] **01. 미션 이동 대상 일치** — 지정 카드와 미달성 조건을 유지한다. 무관한 강화 가능 카드로 대체하지 않고, 복수 후보는 목표에 기여하는 카드에서 선택한다. 이미 달성한 목표는 재행동 대신 달성 상태·보상·다음 행동을 보여준다.
- [ ] **02. 준비 부족 상태 안내** — 미보유·성장 부족·재화 부족·미편성을 구분한다. 기존 도메인과 서버 응답에 근거한 비용·부족량, 현재 이용 가능한 획득·수급 경로를 보여준다.
- [ ] **03. 돌보미 성장 → 편성 안내 연결** — 지정 3종 성장 완료 후 활성 덱이 없어도 편성 방법을 확인할 수 있게 한다.
- [ ] **04. 시너지 해금·준비·활성 표시 구분** — 덱 편집에서 참여 카드·장수·충족 상태를 표시하고 활성 후 실제 효과를 확인한다. 다른 시너지 소개 완료와 무관하게 조건·효과 도움말을 열람할 수 있게 한다.

참고 지점: `GuideMissionNavigator`, `MissionContentNavigation`, `GuideMissionPreparation`, `OutgameTutorialGuide`, `SynergyIntroduction`.

#### 2단계. 자율 챕터를 짧은 도움말로 전환

- [ ] **05. FTUE 졸업 후 미션 진입 안내** — 미션 위치를 짧게 소개한다. 소개를 닫아도 목표·진행·보상·이동 방법을 계속 찾을 수 있게 한다.
- [ ] **06. 후속 챕터 개입 축소** — 카드 강화·키워드 강화·모험·해금 소개를 현재 화면에서 끝나는 도움말로 정리한다. 설명 완료에 따른 자동 화면 닫기와 사용자 선택 없는 전투 진입을 제거한다.
- [ ] **07. 성장 결과와 능력 설명 연결** — 실제 해금된 능력과 선택적 데모를 제공한다. 이미 성장한 계정에 재소비를 요구하지 않는다. `guide.05` 문구는 보유 카드 1장 2성 도달 판정과 일치시킨다.
- [ ] **08. 닫기·미루기·재열람 지원** — 긴 시범은 요청 시 실행한다. 중단·화면 이탈 후 입력 차단·강조·보류 요청을 정리한다. 세션 미루기를 유지하고 재접속 시 미완료 안내의 연속 자동 재생을 방지한다.

참고 지점: `OutgameTutorial.asset`, `OutgameTutorialRunner`, `OutgameTutorialBridge`, `OutgameTutorialGateUI`, `CardDetailOverlayView`, `UnlockIntroOverlay`.

선행 결정: 자동 힌트 허용 범위. **첫 성장 도움말 변경 전에는 11번의 혜택 결합을 먼저 확인한다.** 스텝 축소가 무료 혜택을 잃게 만드는 경우, 해당 경로의 혜택 분리를 먼저 처리한다.

#### 3단계. 책임·저장·서버 혜택 분리

- [ ] **09. FTUE·미션·도움말·해금 책임 분리** — 도움말 미완료가 졸업·미션 달성·보상 수령·기능 이용을 막지 않게 한다. 후속 도움말을 FTUE와 독립적으로 저작할 수 있게 한다.
- [ ] **10. 표시 충돌과 보류 요청 정리** — 공용 조정은 표시 가능 여부와 우선순위를 담당한다. 화면·대상 변경 시 오래된 요청을 취소하고 보상·성장·해금 연출 중첩을 정리한다.
- [ ] **11. 첫 성장 혜택을 도움말 스텝에서 분리** — 서버가 자격·소진을 판정한다. 유지하기로 한 혜택은 도움말 생략으로 잃지 않게 하며, 비용 표시와 요청을 일치시킨다. 응답 유실·재접속 후 중복 지급과 재소비를 방지한다.
- [ ] **12. 기존 계정 전환·복원 처리** — FTUE 저장 좌표·졸업 판정을 유지하고 기존 자율 완료·중단 기록을 해석한다. 도움말 이력 초기화가 보상·혜택 재지급으로 이어지지 않게 한다. 저장 변경 시 읽기·쓰기·서버 채택 경로를 함께 검증한다.

참고 지점: `OutgameTutorialProgress`, `GuidanceCoordinator`, `TutorialGrantsCloud`, 세이브 읽기·쓰기·서버 채택 경로.

선행 결정: 무료 1회 유지 여부와 지원 형태, 기존 소진 기록 연결 방식, 도움말 저작·저장 위치, 기존 자율 기록 전환 정책. 2단계에서 필요한 결정과 호환성 검토는 이 단계까지 미루지 않는다.

#### 4단계. 미션 자유도 조정

- [ ] **13. 입문 미션·경제 정책 확정** — 첫 돌보미 고정 여부, 이후 지정 카드 범위, 대체 목표 수, 순차 수령 완화 범위를 결정한다. 필수 카드 확보·재화 선지급 경로와 다른 카드에 먼저 투자한 계정의 진행 경로를 검증한다.
- [ ] **14. 추천 목표 선택·미루기 적용** — 확정 정책에 따라 추천을 바꾸거나 미뤄도 기존 진행도를 유지한다. 이미 달성한 다른 목표를 확인할 수 있게 하고 추천 선택과 보상 수령 자격을 구분한다.
- [ ] **15. 확정 정책을 미션 데이터·서버·문구에 반영** — 목표·수령 판정·화면 설명을 일치시킨다. 소급 달성·최고 달성 보존을 유지한다. 모험 클리어 조건에 시너지 덱 사용을 안내 작업만으로 추가하지 않는다.

참고 지점: `MissionManager`, `GuideMissionTrack`, `guideProgress.ts`, `judgeMissionClaim.ts`, `claimMission.ts`, 미션·보상 CSV.

의존성: **13번 정책 결정과 경제 검증 후 14~15번을 진행한다.** 목표 추천 변경과 순차 보상 제한 완화는 별개 결정이다. 정책 검토 자체는 1~3단계와 병행할 수 있다.

#### 5단계. 검증·측정

- [ ] **16. 컴파일·서버 판정·플레이 회귀 검증** — 신규·FTUE 진행 중·졸업·선행 달성·미보유·재화 부족·다른 카드 선투자·도움말 중단 계정의 경로를 확인한다. 화면 이탈·재접속·응답 유실·연출 중첩을 포함하며, 변경 범위에 맞는 Unity 컴파일과 서버 판정 검사를 수행한다.
- [ ] **17. 경험 지표 수집과 기준선 확보** — TR-14의 지표 수집 가능 여부를 확인하고 변경 전 기준선을 확보한다. 최종 플레이 검증에서 자발적 성장·편성·실전 활용, 정체 원인, 반복 노출·입력 차단의 변화를 비교한다. 목표 수치는 기준선 확보 후 결정한다.

16번은 각 단계에서 관련 경로를 검증한 뒤 마지막에 전체 여정을 확인하는 작업이다. **17번의 수집 가능 여부 확인과 기준선 측정은 초반에 착수한다.** 변경 전 자료를 확보하지 못했다면 그 한계를 기록하고 개선 효과를 단정하지 않는다.

#### 다음 작업 세션의 사용 규칙

- 세션 시작 시 첫 미완료 태스크와 선행 결정을 확인한다. 현재 기본 착수 범위는 **01~03**, 이어서 **04**다.
- 본문의 진단은 조사 시점 HEAD 기준이다. 관련 타입·에셋·현재 변경분을 확인한 뒤 작업하며, 클래스 구성·메서드·서버 스키마는 이 목록으로 확정하지 않는다.
- 정책이 미결이면 결정이 필요한 항목을 기록하고 독립적으로 가능한 작업을 진행한다. 착수 순서 합의를 미션 정책·밸런스·배포 승인으로 해석하지 않는다.
- 태스크 완료는 구현과 관련 검증을 마친 뒤 표시한다. 세션 종료 시 아래 인계 기록에 완료·진행 중 ID, 결정 사항, 변경 범위, 검증 결과·미검증 사항, 다음 착수 ID를 남긴다.
- 코드·CSV·서버 배포·시트 업로드·생성 산출물의 반영 여부를 각각 보고한다. 스펙 값은 CSV에서만 변경하고 `SpecData.bytes`를 수정·재생성하지 않는다. 시트 스키마 변경·산출물 갱신은 별도 명시적 지시 범위에서 다룬다.

- [ ] FTUE 졸업 이후 도움말 미완료가 자유 플레이를 막지 않는다.
- [ ] 가이드 미션에서 목표·진행·보상·이동 방법을 확인할 수 있다.
- [ ] 단순 컬렉션 진입으로 긴 강제 조작 시퀀스가 자동 시작되지 않는다.
- [ ] 후속 설명 종료 후 카드 상세·도감이 자동으로 닫히지 않는다.
- [ ] 도움말을 닫거나 생략해도 미션 달성·수령·기능 이용 자격이 변하지 않는다.
- [ ] 도움말을 다시 열어볼 수 있고, 이미 성공한 조작의 재소비를 요구하지 않는다.

### 목표 연결

- [ ] 지정 카드 미션 이동에서 무관한 카드로 대상을 바꾸지 않는다.
- [ ] 미보유·성장 부족·재화 부족·미편성을 구분해 보여준다.
- [ ] 해결 경로는 현재 이용 가능한 콘텐츠와 실제 데이터에 근거한다.
- [ ] 지정 3종 성장 완료·미편성 계정이 활성 덱 없이도 편성 방법을 볼 수 있다.
- [ ] 준비 완료와 실제 시너지 활성 완료의 문구·표시가 구분된다.
- [ ] 이미 활성화한 계정에 재편성이나 불필요한 재성장을 요구하지 않는다.
- [ ] 돌보미 소개 미완료여도 다른 시너지의 조건·효과를 열람할 수 있다.
- [ ] 모험 미션의 실제 판정과 권장 덱 사용 안내를 혼동하지 않는다.

### 상태와 복구

- [ ] 화면 이탈·도움말 닫기 후 입력 차단과 강조가 남지 않는다.
- [ ] 화면을 떠난 뒤 보류 요청이 엉뚱한 화면에서 재생되지 않는다.
- [ ] 재접속 시 미완료 도움말이 연속 자동 재생되지 않는다.
- [ ] 서버 성장 성공 후 응답 유실에서도 중복 혜택과 불필요한 재소비가 없다.
- [ ] 미션 소급 달성과 최고 달성 보존이 유지된다.
- [ ] 미션 수령·혜택 소진의 서버 권한이 유지된다.
- [ ] 기존 FTUE 진행 중 계정과 졸업 계정의 저장 상태가 올바르게 해석된다.
- [ ] 보상·성장·해금·안내가 겹쳐도 현재 피드백과 입력 경로를 잃지 않는다.

### 자유도와 검증

- [ ] 첫 시너지 고정 여부와 추천·수령 정책이 결정되어 화면·서버·문구에 일관되게 반영된다.
- [ ] 미션 정책 변경 시 필수 카드 확보와 재화 선지급 경로를 다시 검증한다.
- [ ] 다른 카드에 먼저 투자한 계정의 다음 행동을 확인한다.
- [ ] 신규 계정, 선행 달성 계정, 대상 미보유 계정, 재화 부족 계정, 도움말 중단 계정으로 플레이 검증한다.
- [ ] 변경 범위에 맞는 Unity 컴파일·서버 판정 검사와 실제 플레이 확인을 수행한다.
- [ ] 코드·CSV·서버 배포·생성 산출물의 반영 여부를 각각 보고한다.
- [ ] 전환·정체·반복 노출의 기준선을 측정하고 도움말 완주율만으로 성공을 판정하지 않는다.

## Open Questions

| 항목 | 권장 방향 | 결정에 필요한 판단 |
|---|---|---|
| 첫 시너지 고정 여부 | 첫 체험만 짧은 입문 과제로 고정하거나, 소유 상태에 맞는 조합을 추천 | 확정 지급·재화 지원 비용과 덱 선택 자유도의 균형 |
| 지정 카드 미션 범위 | 첫 체험 이후 결과 중심 목표로 확대 | 콘텐츠 학습 순서와 수집·덱 빌딩 의도 |
| 목표 미루기·선택 | 추천 목표는 미루고 다른 가능한 목표를 볼 수 있게 함 | 한 번에 보여줄 목표 수와 화면 부담 |
| 순차 수령 제한 | 교육에 필수인 의존만 남기는 방향 검토 | 보상 선지급·카드 확보·기존 달성 기록 영향 |
| 자동 도움말 허용 범위 | 짧은 첫 힌트와 결과 알림 중심, 긴 시범은 요청 시 | 어느 순간에 어느 정도 개입이 필요한지 플레이 검증 |
| 첫 성장 혜택 | 안내 스텝과 분리된 서버 자격으로 유지 | 무료 1회 유지 여부, 소진 기록 연결과 비용 표시 |
| 기존 자율 완료 기록 | 실제 행동 상태를 활용해 재학습 최소화 | 기존 계정 분포와 저장·서버 채택 계약 |
| 후속 도움말 저작 위치 | FTUE와 독립 편집 가능한 단위 | 공용 부품 재사용 범위와 실제 에디터 작업 동선 |
| 성공 목표값 | 기준선 측정 후 설정 | 첫 세션 길이·신규 유저 표본·이벤트 수집 가능 여부 |

현재 세션의 최종 제안은 **“FTUE 졸업 → 가이드 미션으로 목표 제시 → 필요한 순간의 도움말”**이다. 가장 먼저 해결할 항목은 돌보미 성장과 편성 안내의 연결, 미션 이동 대상의 일치, 자율 챕터의 과도한 입력 개입이다.
