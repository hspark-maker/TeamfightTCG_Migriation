# Mission Cut-In Lifecycle PRD

문서명: `mission-cut-in-lifecycle.md`

상태: 구현 완료 · 로컬 C# 컴파일 통과 · Unity 플레이 및 모바일 실기기 검증 대기

## Overview

로비 미션 컷인이 씬 전환·모바일 앱 이탈·트윈 중단 이후 화면에 남는 문제를 해결한다.

컷인은 서버에서 확정된 미션 진행을 알리는 비차단 UI다. **랭크·보상 등 다른 로비 연출과 중첩되는 동작은 유지한다.**

현재 코드에서 확인한 체류 가능 경로:

- 재생 중 전투 진입 → 컷인 트윈 일시정지, 현재 알림 유지.
- 전투 종료의 `BattleCleanup.Run()` → `DOTween.KillAll()`로 컷인 트윈 제거.
- 종료 처리가 `OnComplete`에만 연결돼 현재 알림 상태 잔존.
- 로비 복귀 → 죽은 트윈을 재개하려 하며 화면만 다시 표시.

모바일 앱 이탈·복귀에 대한 컷인 전용 처리도 없다. 실제 제보 상황과 위 경로의 일치 여부는 재현 검증이 필요하다.

## Goals

- 보장한다: 정상 완료·외부 중단 이후 컷인 화면과 재생 상태 정리.
- 방지한다: 죽은 트윈을 현재 알림으로 계속 표시하는 상태.
- 정의한다: 전투 진입 및 모바일 백그라운드 진입 시 알림 처리.
- 유지한다: 다른 로비 연출과 의도된 중첩.
- 분리한다: 서버 상태 채택, 대기 알림 관리, 개별 알림 재생 책임.

## Out of Scope

- 로비 전체 연출을 단일 큐로 통합.
- 랭크·보상 연출 때문에 컷인을 추가로 대기시키는 변경.
- 미션 진행·보상·서버 판정 및 스펙 데이터 변경.
- 컷인 디자인·기본 재생 시간 변경.
- 대기 알림의 시간 기반 만료 정책 신규 도입.
- 전투 전체 트윈 소유권 개편. 별도 후속 작업으로 분리.

## Technical Requirements

### 1. 책임 경계

| 구성 | 책임 |
|---|---|
| `MissionManager` | 서버가 확정한 미션 상태 채택 |
| `MissionProgressNotifications` | 진행 차이 감지, 대기 알림 병합, 유효성 검사 |
| `MissionCutInView` | 현재 알림 한 건의 재생·중단·종료 |

서버 응답은 상태와 대기 큐를 갱신한다. 현재 컷인의 재생 시간을 연장하거나 트윈을 다시 시작하지 않는다.

### 2. 종료 보장

다음 경로 모두에서 트윈 참조, 현재 알림 상태, 알파, 위치 및 배율을 일관되게 정리한다.

- 정상 재생 완료.
- 외부 트윈 Kill.
- 명시적 Hide.
- 컴포넌트·오브젝트 비활성화.
- 로비 씬 이탈.
- 모바일 백그라운드 진입.
- 오브젝트 파괴.

종료 처리는 중복 호출에 안전해야 한다. `OnKill`과 내부 `Kill()` 사이의 재귀, 이전 재생 콜백이 다음 알림을 종료하는 상황을 방지한다.

현재 알림이 존재해도 트윈이 없거나 유효하지 않으면 종료한다. 알파를 다시 올리거나 죽은 트윈에 재개를 반복하지 않는다.

### 3. 매치 단계·이탈·복귀 정책 — 확정

| 상황 | 처리 |
|---|---|
| 매치 진입 시작·덱 선택 | 재생 중 알림 즉시 종료. 대기 큐로 되돌리지 않음. 신규 알림 소비 중단 |
| 상대 탐색 중 | 대기 알림 소비 및 재생 허용 |
| 상대 탐색 종료·상대 확정 | 현재 알림 종료. 상대 확정 연출부터 전투 진입까지 신규 소비 중단 |
| 매치 취소·진입 실패로 로비 복귀 | 종료한 알림은 재생하지 않음. 유효한 대기 알림 소비 재개 |
| 고정 상대 모험·튜토리얼 진입 | 탐색 구간이 없으므로 진입 시작부터 신규 소비 중단 |
| 로비 씬 이탈 | 재생 중 알림 종료. 대기 큐로 되돌리지 않음 |
| `OnApplicationPause(true)` | 재생 중 알림 종료, 신규 알림 소비 중단 |
| 앱 복귀 | 기존 알림 재개 없이 대기 알림 유효성 검사 후 소비 |
| 백그라운드 중 서버 응답 채택 | 상태·큐 갱신 가능. 화면 재생은 복귀 후 수행 |
| 포커스만 상실 | 앱 이탈로 단정하지 않음 |

컷인 종료는 **표시만 종료**한다. 미션 진행·달성·보상 수령 상태를 변경하지 않는다.

계정·기간·정의·진행 상태에 대한 기존 알림 유효성 검사를 유지한다. 이탈 외의 기존 일시 대기 조건은 유지하되, 재개 시 트윈 유효성을 확인한다.

### 4. 표시 상태 계약

상주 설치 여부, 현재 알림 보유 여부, 실제 표시 여부를 구분한다.

- 알파를 재생 상태의 유일한 근거로 사용하지 않는다.
- 종료 후 `IsPlaying`은 반드시 false가 된다.
- 풀의 표시 판정에서 대기 중인 상주 컷인은 화면 점유로 취급하지 않는다.
- 기존 해금 안내와의 대기 관계는 유지한다.
- 상태 계약 정리는 컷인과 해당 소비자 범위로 제한한다.

### 5. 전역 트윈 제거 대응

이번 수정은 `BattleCleanup.Run()` 내부의 `DOTween.KillAll()`이 유지돼도 정상 동작해야 한다.

전투 소유 트윈만 정리하도록 범위를 줄이는 작업은 후속 과제로 둔다. 컷인 버그 해결의 선행 조건으로 삼지 않는다.

### 6. 진단

개발 환경에서 다음 상태 전환을 확인할 수 있어야 한다.

- 알림 식별자와 재생 회차.
- 시작·완료·중단 및 종료 사유.
- 씬과 앱 일시정지 상태.
- 현재 알림 보유 여부와 트윈 활성 상태.

매 프레임 로그 대신 상태 변경 시 기록한다. 같은 알림의 고착과 여러 알림의 연속 재생을 구분할 수 있어야 한다.

## Acceptance Criteria

- [ ] 정상 알림은 기존 시간과 연출로 종료된다.
- [ ] 등장·체류·퇴장 중 외부 Kill을 각각 실행해도 화면과 재생 상태가 정리된다.
- [ ] 매치 진입·덱 선택 중 컷인이 즉시 종료되고 신규 알림을 소비하지 않는다.
- [ ] 상대 탐색 중에만 매치 흐름 내 알림 소비가 허용되고 상대 확정 연출 전에 종료된다.
- [ ] 매치 취소·진입 실패 후 유효한 대기 알림을 다시 소비한다.
- [ ] 컷인 도중 전투 진입 후 로비로 복귀해도 이전 컷인이 다시 표시되지 않는다.
- [ ] 홈 이동·화면 잠금 후 짧게 또는 장시간 뒤 복귀해도 컷인이 고착되지 않는다.
- [ ] 백그라운드에서는 신규 알림을 소비하지 않는다.
- [ ] 복귀 후 유효한 대기 알림이 정상적으로 재생된다.
- [ ] 지연 응답이 도착해도 현재 알림의 재생 시간이 초기화되거나 연장되지 않는다.
- [ ] 계정·기간이 달라져 무효가 된 알림은 표시되지 않는다.
- [ ] 랭크 승급·보상 팝업과 기존 중첩 동작이 유지된다.
- [ ] 컷인 종료 후 해금 안내가 잔존 재생 상태 때문에 차단되지 않는다.
- [ ] 종료 중복 호출 및 이전 콜백으로 다음 알림이 취소되지 않는다.
- [ ] Android·iOS 실기기 검증 결과를 각각 기록한다. 미검증 플랫폼은 명시한다.

## Open Questions

- **발생 조건 확인:** 실제 체류가 전투 왕복, 앱 복귀, 최초 로비 진입 중 어디에서 발생했는지.

## 구현·검증 기록 (2026-09-14)

- `MissionCutInView`: 완료·Kill·Hide·비활성화·씬 이탈·앱 백그라운드·파괴 종료 통합. 재생 회차 검증과 참조 선해제로 중복 종료 및 과거 콜백 격리. 실제 표시 판정은 알파 대신 현재 알림·유효 트윈·일시대기 상태를 사용한다.
- `LobbyMatchLauncher`: 진입 시작 시 종료·소비 차단, 취소·실패 시 소비 재개. `MatchmakingShell`: 상대 탐색 왕복만 소비 허용, `finally`에서 종료하여 확정 연출 전에 차단한다.
- 기존 서버 채택·큐 병합·유효성 검사와 풀의 비표시 컷인 제외 경로는 유지한다. 서버·스펙 데이터·프리팹 변경 없음.
- 통과: 변경 C# 파일 `git diff --check`, Unity 6000.3.10f1 Roslyn 및 기존 Bee 응답 파일 설정으로 전체 `Assembly-CSharp` 컴파일(종료 코드 0). DLL 출력은 OS 임시 폴더에 격리했다.
- Unity Editor 플레이 검증: 미실행. MCP가 `COMPILATION_IN_PROGRESS`를 반환했다. 로컬 컴파일 통과는 에디터의 어셈블리 재로드나 플레이 통과를 의미하지 않는다.
- Android 실기기: 미검증. iOS 실기기: 미검증. 위 Acceptance Criteria 체크박스는 런타임 검증 후 갱신한다.
- 런타임 검증 시 등장·체류·퇴장 각각 외부 Kill 및 `DOTween.KillAll()`, Hide/비활성화 중복, 매치 단계 왕복, 백그라운드 응답, 계정·기간 변경, 랭크·보상 중첩, 해금 안내 진행을 확인한다. 개발 로그의 `mission`·`playback`·`reason`으로 고착과 연속 재생을 구별한다.
