## 범위와 한계

현재 저작 `Assets/SO/TutorialConfig/Outgame/OutgameTutorial.asset`의 강제 4챕터·23스텝을 실행기, 화면 완료 신호, 저장, 전투 진입·복귀까지 추적했다. 연결된 가이드 미션의 무료 강화와 서버 명령 재개도 점검했다. 단계 번호는 고유 ID라 연속 번호가 아니다.

## 이번 점검에서 수정한 경로

- **Dim 없는 강제 단계의 다른 조작:** 활성 강제 스텝도 공통 입력 잠금에 포함했다. 게이트는 투명 차단판으로 대상만 허용한다. 팩 개봉·도감 삽입 자체 입력은 유지한다. 최종 전투 인계처럼 현재 스텝이 없는 동안에는 덱 확인·취소를 허용한다.
- **팩 결과 카드 상세로 이탈:** 자체 카드 입력이 게이트를 거치지 않아 닫기가 제한된 상세 화면으로 들어갈 수 있었다. 상세 열기에도 현재 안내 대상 검사를 적용했다. 가이드가 요구한 도감 카드 열기와 내부 화면 복원은 허용한다.
- **화면 복구가 진행을 되감음:** 현재 단계의 탭·덱 편집기·도감 표면만 복원한다. 이전 설명이나 진입 효과를 다시 실행하지 않는다. 도착 대기에는 취소·시간 제한을 유지한다.
- **대본 없는 마지막 전투의 체크포인트 누락:** 모든 강제 전투 진입을 기록한다. 마지막 좌표까지 이동했더라도 미완료 전투 기록이 남으면 졸업하지 않는다.
- **전투 진입 실패·취소 뒤 안내 소실:** 진행 저장 왕복이 끝난 뒤 전투 진입 단계로 복원하고, 전용 이벤트로 브리지를 재개한다. 일반 단계 변경 이벤트에 구독하지 않아 씬 이동 중 다음 단계가 조기 실행되지 않는다.
- **무효 경기 복귀:** 결과 없이 돌아오면 전투 진입을 복원한다. 정상 결과는 미완료 기록을 해제한다. 로비 복귀 커버 아래에서 진행 저장을 확인한 뒤 안내를 연다.
- **무료 강화 응답 유실:** 서버가 이미 소진한 무료 요청을 `NotReady`로 거절하면 클라이언트도 무료권 표식을 다시 읽는다. 확인 실패를 완료로 처리하거나 유료 강화로 재요청하지 않는다.

기존 변경의 탭 도착 판정, 중복 완료 방지, 같은 대기 단계 재진입 방지, 소개마다 완료 저장, 해금 화면·승급·보상 연출 수명 동안 하단 버튼 차단도 함께 검증한다.

## 서버 계약

구매·지급 전 명령 저널 저장을 확인하고 동일 요청 ID로 복구한다. 영구 `onboardingOperations`가 일반 영수증 만료 후에도 중복 집행을 막는다. 유실 응답 복구는 당시 명령 결과와 최신 저장 상태를 분리한다. 튜토리얼 카드 재지급은 소유 합집합이며 기존 성장값을 초기화하지 않는다.

서버가 모든 UI 단계의 정당성을 검증하는 구조는 아니다. 서버 저장이 확정되기 전 앱이 종료되면 마지막 미확정 설명·연출은 다시 나올 수 있다. 이를 모든 종료 시점의 무재생 보장으로 해석하지 않는다.


실제 C# 메서드를 매 실행 시 추출하고 UI·서버·Unity 플레이 루프 경계만 대체한다. 결과물은 OS 임시 폴더에 만든다. 재진입·동시 완료·저장 실패, 전투 미완료/정상 결과, 무료 강화 거절 복구, 강제 입력 정책과 화면 복원을 검사한다.

이번 실행에서 런타임·에디터 C# 컴파일, 기존 재진입 회귀, 전투 체크포인트 12개, 무료 강화 복구 80조합, 현재 저작 23스텝을 포함한 입력·복원 정책 1,206개 검사가 통과했다. 검사 개수는 관리형 단언 수이며 실제 플레이 횟수가 아니다.

서버는 현재 TypeScript를 OS 임시 폴더로 컴파일한 뒤 온보딩 멱등성, 시너지 지급, 가이드 성장, 가이드 카탈로그 회귀를 실행했다. 기존 `functions/lib`와 원격 서버는 변경하지 않았다. 스펙 CSV·`SpecData.bytes`·프리팹도 이 점검에서 수정하지 않았다.
