# 초기 일반 카드 6장 — 기본 세트 5장과 파도리 1장

2026-09-17 사용자 지시: 기본 카드 지급을 파도리 포함 일반 카드 6장으로 줄이되, 파도리 한 장을 별도로 보여주는 화면은 유지한다.

- 기본 카드 세트(`TutorialStarterGrant`): 포슬램(1), 꿀꿀비(20), 솜구름몽(4), 물방울룽(15), 문바이트(35), 총 5장.
- 첫 승리 보너스(`TutorialFirstCard`): 파도리(2), 1장. 기존 단독 보상 화면·스텝 ID 3·병렬 획득 연출은 그대로 둔다.
- 신규 계정의 서버 소유/초기 덱(`StarterPack`)과 원거리 학습 덱(`RangePack`, `TutorialScenario1.PlayerDeckIds`): `[1, 2, 20, 4, 15, 35]`.
- 모두 현재 Card CSV의 Common 등급이다. 초기 지급과 두 보상 연출을 합쳐도 소유 카드 종류는 6개다.

튜토리얼 카드 지급은 drawCount가 아니라 드롭 풀 전체를 지급하므로 `TutorialStarterGrant` 드롭 행도 7→5개로 줄였다. 중복 여부와 무관하게 저작된 세트를 보여주는 SO 카드 목록을 동일한 5장으로 맞췄다. 원거리 학습은 파도리의 슬롯 1과 첫 3장 순서를 유지했다. 적 덱·공격 스크립트·키워드 팩 개봉 학습은 변경하지 않았다.

기존 스타터에 있던 깜밤이는 후속 가이드 `guide.08`에서 버섯냥과 함께 필수다. 초기 일반 카드 제한을 지키면서 진행이 막히지 않도록 `guide.07`(모험 1장 2번 클리어) 보상에 깜밤이 1장을 추가했다. 기존 버섯냥 보상은 그대로다. 이후 팩 개봉·가이드 보상으로 새 카드를 얻는 진행은 유지한다.

서버의 과거 고정 희귀 카드 폴백 목록은 제거했다. 스타터 표가 없거나 불완전하거나 일반 이외 등급을 담으면 계정 생성/개발 초기화를 진행하지 않고 `unavailable`로 재시도를 요청한다. 카드 구성의 진실원은 CSV로 유지하며 코드에 새 카드 ID 목록을 복제하지 않았다. 기존 소유 카드 회수나 계정 초기화는 수행하지 않았다.

## 검증

- 실제 서버의 스타터 해석·신규 계정 슬롯 생성·튜토리얼 지급 판정 함수에 현재 CSV를 넣어 5+1장, 일반 6종, 초기 덱/소유 일치와 재지급 시 소유 종류 불증가를 확인했다.
- 표 누락·부분 누락·카탈로그 누락·희귀 카드 혼입·읽기 오류에서 과거 폴백 지급이 발생하지 않음을 확인했다.
- TypeScript `tsc --noEmit` 및 변경 서버 파일 ESLint 통과.
- Unity에서 임포트된 실제 SO의 5장 세트·파도리 단독 스텝·6장 덱을 확인했고, 변경 스텝의 저작 검증 오류가 없었다.
- 두 번째 전투는 실제 `PlayerTurn`의 파도리 첫 공격 강제를 적용한 헤드리스 샘플에서 무작위 선택 10,000전과 AI 선택 10,000전 모두 승리, 무승부·패배·정체 0이었다. UI 입력·획득 연출의 실플레이는 별도 검증 대상이다. 첫 공격 강제를 무시한 자유 선택 조건은 무승부가 나올 수 있어 이 결과를 일반 덱 승률로 해석하면 안 된다.
- 유료 팩 가중치, 다른 팩/기존 보상 행, 튜토리얼 나머지 스텝은 이번 변경 전과 동일하다. `SpecData.bytes` 및 자동 생성 C#은 변경하지 않았다.

## 반영 순서

로컬 변경만 완료했다. `CardPack_sheet.csv`, `CardPackDrop_sheet.csv`, `Reward_sheet.csv`를 같은 테이블 릴리즈에 반영하고, 앞선 희귀 승급을 아직 반영하지 않았다면 `Card_sheet.csv`도 포함한다. 이후 수정 서버 코드가 사용되는 `ensureAccount`, `devResetSave`를 배포한다. 새 서버 검증을 옛 희귀 스타터 표보다 먼저 배포하면 신규 계정이 재시도 상태에 머무르므로 표를 먼저 반영한다.

보상 표시와 원거리 덱 구성은 클라이언트의 `OutgameTutorial.asset`, `TutorialScenario1.asset` 변경도 함께 필요하다. 기존 클라이언트는 옛 세트/덱을 사용하므로 개발 환경에서는 테이블·서버·클라이언트를 맞춘 뒤 신규 계정으로 확인한다. 이번 작업에서 테이블 업로드·서버 배포·기존 계정 변경은 수행하지 않았다.
