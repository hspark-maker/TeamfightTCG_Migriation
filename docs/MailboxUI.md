# 우편함 UI

- 로비 우편함 버튼 → `MailboxPanel` 목록 → 우편 상세 → 개별 수령 / 목록의 모두 받기.
- 출석 화면의 크림색 프레임·제목 리본·초록 버튼과 공용 팝업 전환을 재사용한다.
- 봉투와 알림으로 수령 가능 상태를 표시하고, 수령 완료·만료 우편도 열어 볼 수 있다.
- 목록은 20통씩 읽는다. `이전 우편 더 보기`는 서버 커서를 그대로 전달한다.
- 상세 제목·본문은 서식 태그를 해석하지 않으며 긴 본문과 최대 10개 첨부를 스크롤로 표시한다.
- 모두 받기는 서버 계약대로 최대 20통을 처리한다. 남은 우편은 다시 모두 받기로 수령한다.

## 연결

- `Assets/Scripts/OutGame/Mail/MailboxCommands.cs`: `getMailbox`, `claimMail`, `claimAllMail` 호출과 세션별 캐시.
- 수령은 `ServerSaveCommands.InvokeAsync`가 지갑·슬롯·미션·통계 응답을 채택한 뒤 UI에 반환한다.
- 성공한 우편은 즉시 수령 완료로 표시하고 목록을 다시 조회한다. 응답 유실 시 같은 `txId`로 수령 결과를 확인한다.
- 실제 보상 표시는 기존 `MissionPanel.ShowClaimedRewards`를 재사용한다. 결과 DTO만 전달하므로 팝업에서 다시 지급하지 않는다.
- 로비 알림은 진입·앱 복귀·60초 간격으로 조회한다. 우편함을 읽는 동안에는 배경 조회로 목록 페이지를 초기화하지 않는다.
- Addressables 주소는 `MailboxPanel`, 라벨은 기존 출석 UI와 동일하며 `UiPrefabCache`에서 지연 로드한다.

## 저작과 검증

- 프리팹: `Assets/Assets/Prefabs/UI/PooledUI/Progress/MailboxPanel.prefab`.
- `Tools/UI/Build Mailbox UI`는 출석 프레임을 기준으로 우편함 프리팹을 다시 만들고 로비 진입 및 Addressables 등록을 연결한다. 수작업 디자인 수정 후에는 재생성에 주의한다.
- 빈 목록, 조회 실패와 재시도, 수령 완료·만료, 다음 페이지, 긴 본문과 첨부 10개를 확인한다.
- 2026-09-22: Unity 컴파일·초기화, UI 참조 21개·행 참조 9개·로비 버튼과 알림 점·Addressables 등록 확인. 100자 제목·4,000자 본문·첨부 10개 스크롤과 1080×1920/1080×1440 렌더 확인.
- 서비스 코드 오프라인 검증 14개 통과: 페이지 커서·중복 제거·조회 실패·응답 유실 재시도·수령 즉시 반영·일괄 다음 묶음·조회/수령 경합·만료·계정 변경 포함. 실제 서버 수령은 검증하지 않았다.
- 2026-09-22: `bm-cardbattle`의 `asia-northeast3`에 [우편함 서버 API](MailboxServer.md) 함수 4개를 배포하고 모두 `ACTIVE`인 것을 확인했다. `cardbattle` DB 인덱스 배포도 완료했다. 기존 설치 앱에서 새 UI를 사용하려면 앱 코드와 리소스도 함께 반영해야 한다.

사용자 요청에 따른 현재 계정 테스트 우편 발송과 실제 게임 확인은 아직 미완료다. Unity MCP의 `Connection revoked`로 현재 계정을 확인할 수 없어 발송하지 않았다. Addressables 배포와 실제 서버 수령도 수행하지 않았다.
