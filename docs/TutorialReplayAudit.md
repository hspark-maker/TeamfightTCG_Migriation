## 발견한 반복 경로와 수정

- **서버 응답으로 해금 이력 역행:** 경험치·미션 응답의 Profile 사본에 과거 `ContentUnlocks.Pending`이 남아 있으면, 로컬에서 막 완료한 소개가 다시 대기열에 들어갔다. `DataSaveManager.AdoptServerSlots`는 클라이언트가 관리하는 기존 `ContentUnlocks`를 보존하고 서버 경험치·보상 필드는 채택한다. 새 로그인 전체 세이브 채택은 원격 이력을 그대로 사용한다.
- **같은 스텝 재진입:** 팩 화면 열림·닫힘이나 무료권 갱신 신호가 대기 중인 스텝을 다시 진입시키면서 연출을 닫고 재시작할 수 있었다. `OutgameTutorialBridge`는 현재 실행 세션과 스텝이 같으면 진입을 반복하지 않고 현재 화면만 갱신한다.
- **완료 후 저장 실패:** 사용자가 안내를 끝내도 완료 전 저장이 실패하면 같은 스텝에 남는다. 재시도에서 완료된 스텝의 진입 명령·보상 팝업을 다시 실행하지 않고, 미확정 서버 명령 복구와 완료 저장만 이어간다. 이 완료 의도는 현재 브리지 수명 안에서 보존한다.
- **해금 소개 간 저장 공백:** 각 소개가 끝난 뒤 서버 저장이 확인되어야 다음 소개로 넘어간다. 마지막 졸업 소개처럼 로컬 대기열이 이미 비었거나 현재 가이드 미션이 없어도 실패한 저장을 재시도할 수 있도록 흐름을 보관한다. 이미 완료한 가이드의 소개 이력만 남은 경우에는 안내 챕터를 다시 열지 않는다.
- **무료 강화 중복 요청의 유료 전환:** 소진된 무료권에 다른 요청 ID가 붙어 오면 유료 강화로 진행될 수 있었다. 서버 카드·키워드 강화는 해당 요청을 `NotReady`로 거절하며, 성장과 재화를 변경하지 않는다. 명시적 유료 강화는 유지한다.
- **향후 저작 중복:** 가이드끼리의 소개 중복뿐 아니라 FTUE와 가이드 흐름 간 같은 콘텐츠 소개도 `GuideMissionFlowValidation`이 검사한다.

## 서버 확인 범위

동일 요청 ID는 Firestore 트랜잭션과 영구 `onboardingOperations` 기록으로 재집행을 막는다. 일반 영수증 TTL이 만료되어도 온보딩 기록은 유지된다. 응답을 잃은 요청은 `getOnboardingOperation`에서 당시 결과와 최신 세이브·지갑을 분리해 복구한다. 요청 계정·명령·인자도 대조한다.

튜토리얼 카드 지급은 지급 이력과 소유 변경을 같은 트랜잭션에 반영한다. 이미 가진 카드를 다시 지급해도 소유는 합집합으로 처리하고 기존 성장값을 초기화하지 않는다.

튜토리얼 커서와 소개 완료 이력은 클라이언트가 서버 세이브에 저장하는 구조다. 서버가 모든 UI 단계의 정당성을 판정하는 구조로 바꾸지는 않았다. 서버 확인 이전에 프로세스가 종료되면 마지막 미확정 단계가 다시 나올 수 있으며, 이번 변경을 모든 강제 종료 시점에 대한 무재생 보장으로 해석하지 않는다.

## 검증과 반영 상태

- C# 런타임·에디터 어셈블리 컴파일.
- 실제 저장 매니저와 저장 모델을 실행해 오래된 서버 Profile 응답, 새 해금 대기, 반복 응답, 경험치·보상 채택, 새 로그인 채택을 검사. 수정 전에는 완료 이력 보존 검사가 실패함을 확인.
- 실제 서버 코드의 온보딩 영수증 회귀: 동일 요청, 영수증 TTL 만료, 요청 ID 재사용 오류, 응답 유실 복구, 최신 상태 보존.
- 카드·키워드 무료 강화의 첫 지급, 중복 거절, 잔액·성장 보존, 명시적 유료 요청 검사.
- 실제 저작 검증기를 실행해 FTUE 내부·FTUE와 가이드 간 중복 및 정상 구성을 검사.
- `scripts/test-tutorial-replay.ps1`: 실제 브리지 메서드와 `OnboardingSession`을 관리형 하네스에서 실행해 대기 스텝 재진입, 첫·두 번째 완료 저장 실패, 중복 완료 신호를 검사한다. Unity UI·서버 경계는 대체한다.
- 소개 저장 재시도 분기를 실행해 마지막 소개 완료 후 대기열과 현재 미션이 없어도 저장을 이어가는지, 실패 후 재시도 기록이 유지되는지 검사.

Unity MCP 연결이 해제되어 실제 화면을 처음부터 끝까지 플레이하거나 실 Firebase 장애를 주입한 검증은 하지 못했다. 서버 변경은 배포하지 않았으며, 스펙 시트·`SpecData.bytes`는 이 작업에서 변경하지 않았다.
