# 랭크 AI 성장 프로필 저작 상태

2026-09-11. `RankAiEncounter_sheet.csv`는 **일반전 초기 곡선 후보**다. 실제 플레이와 전투 시뮬레이션으로 밸런스를 검증하지 않았다. 숫자 진실원은 CSV이며, 이 문서는 저작 의도와 검증 범위만 설명한다.

같은 날 샤드 누적 강화 기준으로 로컬 CSV를 재조정하고 등급 승급전 프로필과 서버 선택 코드를 추가했다. 아래 성장 곡선은 재조정본이며, 기존 테스트 공개본 5.21에는 아직 반영하지 않았다. 표 변경 대상은 `RankAiEncounter`와 `AdventureChapter`다. 컬럼 계약·테이블 세대는 변경하지 않았다. 승급전 적용에는 `RankAiEncounter` 161행 발행 후 `findAiMatch` 배포가 필요하다.

## 작성 범위

- `AIDeck_sheet.csv`의 랭크 후보 22덱을 기존 `fromTier`~`toTier` 범위 그대로 확장한 Normal 136행. 모험 전용 12덱은 제외한다.
- 카드 구성·후보 가중치·기존 공통 레벨은 AIDeck 원본 그대로다. 신규 표에는 카드별 성장값만 저작했다.
- 설명·필드명·타입의 3행 헤더를 사용한다. `#memo`는 설명용이다. `tierIndex + battleKind + deckId`는 유일해야 한다.
- `id`는 처음 부여할 때 `10000 + tierIndex * 100 + AIDeck.id`로 배정했다. 부여 후 변경하지 않는다.
- Normal 136행과 GradeFinal 25행을 포함한다. 등급 내부 단계 이동용 `DivisionFinal`은 추가하지 않았다. 현재 게임에서 승급 대기 UI와 별도 승급 정산이 있는 등급 승급전만 강화한다.
- 서버 조회·선택 코드와 에디터 발행 스키마를 연결하고, 테스트 환경 `5.21`에 136행을 발행했다. `findAiMatch`·`submitMatchResult` 배포도 완료했다. 라이브 스펙, `SpecData.bytes`, 자동 생성 C# 파일은 갱신하지 않았다.

## 스키마·반영 경로

- 스키마는 서버 전용 `RankAiEncounterRow`다. 게임 입력 열 17개이며 `#memo`는 발행에서 제외한다. CSV의 슬롯 번호는 AIDeck 원래 카드 순서를 뜻한다. 서버는 셔플 전에 카드 ID에 성장값과 강조 대상을 연결한다.
- `SpecPayloadCodec.ServerOnlyTableNames`와 `RowTypeOf`에 등록했다. 클라이언트가 내려받는 `TableNames`는 그대로이고 콘텐츠 major는 5다. 새 표는 `SpecLocalTables`가 CSV에서 직접 읽어 `SpecFirestoreUploader`에 넘긴다. 기존 bytes를 내보내며 이 CSV를 덮어쓰지 않도록 보호했다.
- 새 서버는 `aiGrowthVersion:1` 요청에서만 이 표를 사용한다. 구 요청의 AIDeck 공통 레벨과 이미 생성된 매치의 고정 스냅샷은 계속 지원한다. 새 요청에서 프로필이 없으면 임의 덱·공통 레벨로 우회하지 않는다.
- 새 클라이언트의 매칭 테스트에는 RankAiEncounter 공개와 서버 배포가 모두 필요하다. 테스트 환경에서 두 단계를 완료했다. Google Sheet에는 업로드하지 않았으며 저장소 CSV를 직접 발행했다.
- 새 표가 없는 과거 공개본은 새 서버의 Normal 프로필 요구를 충족하지 않는다. 기존 에디터 롤백 검증도 표 누락을 차단한다. 되돌릴 때는 새 표를 포함한 공개본을 사용하거나 서버 코드도 함께 되돌려야 한다.
- 등급 승급전 선택 코드를 배포하기 전에 대상 환경에 GradeFinal 25행을 포함한 표를 발행해야 한다. 기존 Normal 전용 공개본으로 먼저 함수를 교체하면 승급전 후보 누락으로 매칭이 거절된다. 테이블 이름만 검사하는 기존 롤백 검증은 GradeFinal 행 누락까지 보장하지 않으므로, 되돌릴 공개본의 승급전 행도 확인한다.
- `publish-local-spec.js`의 일반 발행은 기존 보상 4표만 지원한다. 이번 최초 발행은 `functions/scripts/publish-rank-ai-test-spec.js`로 기존 22개 표 핀을 보존하면서 신규 표만 추가했다. test 경로 제한, 생성 조건, 인덱스 CAS를 사용하며 변경 계획과 이전 인덱스를 보관한다.

## 성장 곡선

설계 근거는 [랭크 AI 성장·승급전 설계](../RANK_AI_FIRST_HOUR_DESIGN.md)다. 표시 성급은 내부 레벨에서 1을 뺀 값이다.

| 등급 | 티어 인덱스 | IV / III / II / I 성급 합계 | 한계돌파 합계 | 후보 행 수 |
|---|---|---|---|---|
| 브론즈 | 0~3 | 0 / 1 / 2 / 4 | 모두 0 | 2 / 2 / 5 / 5 |
| 실버 | 4~7 | 6 / 8 / 9 / 10 | 모두 0 | 5 / 5 / 4 / 4 |
| 골드 | 8~11 | 11 / 12 / 12 / 13 | 모두 0 | 4 / 12 / 12 / 8 |
| 플래티넘 | 12~15 | 13 / 14 / 14 / 15 | 모두 0 | 8 / 8 / 8 / 8 |
| 다이아몬드 | 16~19 | 16 / 17 / 18 / 18 | 0 / 2 / 4 / 6 | 9 / 9 / 9 / 9 |

브론즈는 여러 카드에 1성씩 배분해 2성 시너지를 열지 않는다. 실버는 1성 6장에서 조합 핵심부터 2성으로 올린다. 골드 III~II는 2성 6장을 유지하고 골드 I에서 첫 3성 에이스가 등장한다. 플래티넘은 3성 1 / 2 / 2 / 3장, 다이아몬드는 4 / 5 / 6 / 6장이다. 다이아몬드에서는 에이스 2장의 한계돌파를 각각 0→1→2→3으로 올린다. 기존 카드별 우선순위는 유지하며, 다이아몬드부터 합류하는 deck_09는 해롱문어·화르룩스·늪꾸리·눈덩곰·자석게·톱니두더 순으로 3성을 배분한다.

현재 강화 비용은 0→1성 10, 1→2성 20, 2→3성 150샤드다. HP 증가량은 각각 1~3 / 1~2 / 8~11이다. 기존 곡선은 골드 II부터 매 티어 150샤드에 해당하는 3성 한 장을 추가하여 플래티넘 I에서 전원 만렙이 됐다. 재조정본은 일부 인접 티어의 성급을 유지해 샤드를 모을 구간을 주고 전원 3성은 다이아몬드 II로 늦춘다. 플레이어 덱 전투력에 따라 상대를 자동 강화하지 않는다.

현재 AI 표는 정수 레벨·한계돌파만 지원하므로 진화 전 샤드 투자량을 새 열이나 숨은 HP 보정으로 추가하지 않았다. 연속 성장은 카드별 진화 시점을 분산하는 방식으로 반영한다. 시너지·키워드 해금 조건은 그대로다.

### 모험 커브

`AdventureChapter.aiCardLevel`의 내부 레벨을 1장 `1 1 1 2 2 2`, 2장 `2 2 2 2 2 2`, 3장 `2 2 3 3 3 3`, 4장 `3 3 3 3 3 3`으로 조정했다. 표시 성급은 여기서 1을 뺀 값이다. 4번 정점 전까지 모험 샤드 보상만 90개이므로 일반·희귀 6장의 1성 비용 60개를 충당한다. 첫 전원 2성 상대인 15번 정점 전까지는 640개를 받아 전원 2성 비용 180개보다 여유가 있다. 이는 전액 수령·강화에 사용했을 때의 수급 근거이며 실제 유저 투자량을 보장하지 않는다. 큰 HP 상승이 있는 전원 3성은 모험 필수 관문으로 추가하지 않는다. 덱·보상·입장 점수는 유지한다.

### 등급 승급전

`findAiMatch`는 서버 랭크 점수로 `computeRankPayout(...).promoBattle`을 조회해 GradeFinal을 선택한다. 현재 표에서 259 / 419 / 579 / 739점이 해당하며 숫자를 함수에 하드코딩하지 않는다. 250점에서 259점에 도달하는 일반전, 등급 내부 단계 이동, 최상위 등급 전투는 Normal이다. 응답의 카드별 성장과 매치에 고정한 스냅샷을 기존 경로로 표시·재생한다. 같은 txId 재요청은 확정한 상대를 그대로 반환한다. 다른 txId도 현재 서버 점수에서 승급전이면 GradeFinal만 추첨하지만, 후보·배치·시드 자체를 재추첨하지 못하게 잠그는 기능은 이번 범위에 포함하지 않았다. 구 aiGrowthVersion 없는 요청은 기존 공통 레벨 계약을 유지한다.

| 승급 | 프로필 수 | 일반전 대비 변화 | 시너지 적용 전 HP 합계 증가 |
|---|---:|---|---:|
| 브론즈→실버 | 5 | 남은 0성 2장을 1성으로 → 전원 1성 | +4 |
| 실버→골드 | 4 | 남은 1성 2장을 2성으로 → 전원 2성 | +4 |
| 골드→플래티넘 | 8 | 차순위 주력 1장을 3성으로 + 기존 에이스 한계돌파 1 | +9~12 |
| 플래티넘→다이아몬드 | 8 | 차순위 주력 1장을 3성으로 + 기존 에이스 한계돌파 1 | +9~11 |

행 ID는 대응 Normal ID + 20000으로 최초 배정했다. 총 161행의 ID·복합키·성장 계약 검증, 0~1000점의 승급 경계 1001개 검사, 실제 findAiMatch 핸들러의 가짜 DB 실행 8개 경계·멱등 재시도 검증, TypeScript 빌드와 변경 코드 ESLint를 통과했다. 실제 서버 호출·발행·함수 배포·완주 전투 검증은 수행하지 않았다.

### 재조정 검증

랭크 70행과 모험 14행의 레벨 값만 변경했다. CSV 열 수·행 ID·후보 범위·나머지 필드 보존을 검사하고, 현재 서버 소스의 파서·가중 추첨·전투 스냅샷 생성기로 랭크 136개 프로필과 모험 24개 정점을 검증했다. 카드별 레벨·한계돌파 비감소, 서사·신화 최소 1성, 시너지·키워드 해금 및 스냅샷 재채택 계약이 통과했다. 새 테스트 스크립트나 생성 산출물은 저장소에 추가하지 않았다.

시너지 효과 적용 전 후보 평균 HP 합계는 골드 I 67.6→58.5, 플래티넘 I 103.1→76.9, 다이아몬드 IV 103.8→86.0이다. 다이아몬드 II·I의 최종 성장량은 유지된다. HP 합계는 전투 승률이 아니며 완주 전투·실제 플레이 난이도는 미검증이다. 아래의 배포·Play 기록은 재조정 전 공개본에 대한 과거 검증이다.

## 남은 밸런스 문제

- deck_12는 낙인 2장이라 필요한 3장에 못 미친다. deck_15·18·22도 현재 구성으로 완성 가능한 시너지가 없다. 같은 티어의 완성 시너지 덱과 승률이 동등하다는 증거는 없다. 이번 작업에서는 기존 덱 카드와 가중치를 유지했다.

### Play 종료 뒤 남는 매칭 실패 팝업 수정

점검용 요청이 Play 종료 후 Firebase 해제와 겹치며 `Callable service is not available for 'findAiMatch'`로 실패했고, 실패 안내가 편집 모드에도 남았다. `ServerMatchmaker` 요청 수명을 호출자 취소 토큰과 `Application.exitCancellationToken`에 연결했다. 편집 모드의 요청, 종료 후 응답 채택, 취소·종료 뒤 지연 팝업을 차단한다. 실제 실패 안내는 계속 다음 프레임에 표시한다.

`Tools/AiMatchGrowthTests/run-lifecycle.ps1`은 실제 팝업 메서드로 정상·사전취소·대기 중 취소·편집 모드·종료·다음 Play 누출 방지 6개 시나리오/15검사를 통과했다. 기존 성장 68검사와 Unity 컴파일도 통과했다.
