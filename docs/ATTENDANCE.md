# 7일 누적 출석

서버가 한국 시간 오전 5시를 기준으로 하루 한 번 보상 수령을 허용한다. 접속하지 않은 날은 누적 일수를 초기화하지 않는다. 7일차 수령 당일에는 완료 상태를 유지하며 다음 출석 가능일부터 새 주기를 시작한다. 출석은 보상 수령 시 확정된다.

로비 왼쪽 출석 버튼으로 열 수 있다. 수령 가능할 때 알림점을 표시하며, 로비 진입 후 다른 팝업·튜토리얼·매치 진입·팩 개봉 연출이 끝나면 하루 한 번 자동으로 연다. 닫기만 한 경우 당일 자동으로 다시 열지 않으며 버튼으로 재진입한다. 앱 복귀와 서버 날짜 경계에서는 상태를 다시 조회한다.

## 보상

값의 진실원은 `docs/SpecData/Reward_sheet.csv`의 `ownerType=Attendance`, `ownerId=day_1`부터 `day_7`까지다. 화면은 `getAttendance`가 내려준 보상을 표시한다. 새로운 시트 스키마는 추가하지 않았다.

| 일차 | 초기 보상 |
|---|---|
| 1 | 골드 110 |
| 2 | 조각 30 |
| 3 | 에너지 10 |
| 4 | 골드 220 |
| 5 | 조각 60 |
| 6 | 다이아 10 |
| 7 | 일반팩 1개 (`NormalPack_TEST1`, 기존 Live 팩) |

기존 미션의 패널·리본·글꼴·버튼·선물 아이콘을 재사용했다. 셀은 일차별 최대 3종 보상을 표시한다. 팩 선택형 보상은 이번 버전에 포함하지 않는다.

## 서버와 클라이언트

- `getAttendance`: 서버 날짜, 다음 갱신 시각, 주기, 수령 일수, 수령 가능 상태, 7일 보상 조회.
- `claimAttendance`: `dailyKey`, `cycle`, `day`, `txId`를 검증하여 출석 기록과 지갑·소유·성장·영수증을 동일 트랜잭션에서 확정.
- 저장 문서: `envs/{env}/users/{uid}/attendance/current`. Admin SDK가 읽고 쓰며 클라이언트는 callable만 사용한다. 기존 기본 거부 규칙을 유지한다.
- 클라이언트 시간 표시는 서버 시각에 경과 시간을 더한다. 기기 날짜를 수령 판정에 사용하지 않는다.
- 통신 실패 후에는 동일 영수증으로 수령 결과를 확인한다. 공용 서버 명령 정책상 다른 명령이 revision을 진행시킨 뒤 과거 영수증을 재생하면 세션 동기화 절차가 필요할 수 있다.
- 보상은 서버 수령 응답 채택 후 공용 보상 팝업으로 표시한다. 7일차 팩은 이미 확정된 결과를 기존 개봉 화면에 전달한다.

## 반영 항목

1. 기존 Reward 표 업로드 경로로 출석 보상 행을 서버에 반영한다.
2. Cloud Functions `getAttendance`, `claimAttendance`를 배포한다.
3. `AttendancePanel` Addressable과 로비 버튼이 포함된 UI 콘텐츠, 신규 C# 코드가 포함된 클라이언트를 빌드·반영한다.

보상표 누락은 출석 기능의 조회 실패로 표시되며 기본 게임 초기화를 차단하지 않는다. `Assets/Resources/SpecData.bytes` 및 자동 생성 테이블은 이번 작업에서 갱신하지 않았다. 서버·콘텐츠 배포도 실행하지 않았다.

## 검증

`functions`에서 `npm run build`, `node scripts/test-attendance.js` 실행. 회귀는 실제 callable·공용 지급/영수증 코드와 메모리 트랜잭션 드라이버를 사용한다. 팩 추첨은 대역이며 Firebase 실서버/에뮬레이터 검증과는 구분한다.

검증 범위: 같은/다른 영수증의 동시 수령, 날짜 경계, 누락 유지, 7일 반복, 응답 유실 재시도, 과거 요청과 신규 날짜 경합, 보상표/아이템 지급 실패 시 무지급.

클라이언트는 전체 C# 컴파일과 프리팹 GUID·참조·계층·일차 배치 검증을 수행했다. Unity 연결이 해제되어 실제 기기/에디터의 자동 팝업·수령·7일차 팩 개봉은 아직 재생 검증하지 못했다.
