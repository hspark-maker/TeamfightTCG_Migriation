# 룰렛 보상 편차 보정

기본 비율은 `docs/SpecData/RouletteSlot_sheet.csv`의 weight를 따른다. 현재 8칸의 가중치는 25/20/25/15/8/4/2/1이며 합계 100이다. 균등 확률로 바꾸지 않는다.

서버는 가중치를 한 주기에서 지급할 횟수로 사용한다. 매 회전은 각 칸의 **남은 횟수 / 전체 남은 횟수**로 추첨하고 당첨 칸의 횟수만 1 감소시킨다. 모두 소진하면 다음 회전에서 새 주기를 시작한다. 예를 들어 첫 회에 25% 칸이 당첨되면 다음 회의 해당 칸 확률은 24/99다. 소진된 칸은 그 주기에서 더 나오지 않는다.

- 보정 단위는 달력 기간이 아닌 플레이어별 회전 횟수다. 같은 판을 각자 100회 돌리면 칸별 당첨 횟수와 룰렛 지급 총량이 같다. 100회 미만 구간은 편차가 남으며, 임의의 연속 100회 구간이 아닌 각 주기에 적용한다.
- 팩 상품의 당첨 횟수는 맞추지만 팩 내부 카드 추첨 및 중복 보상 결과까지 같게 만들지는 않는다.
- 기존 재화 보상 축소는 유지한다: 골드 20/50, 조각 3/8, 다이아 1, 에너지 5. 팩 2칸은 각각 기존 일반 팩 1개로 복원한다.
- 상태는 `envs/{env}/users/{uid}/rouletteCycles/{sha256(rouletteId)}`에 서버만 읽고 쓴다. 로그아웃·날짜 변경으로 초기화하지 않는다. 신규 적용 전 추첨 이력은 소급하지 않는다.
- 지급·티켓 차감·상태 차감·영수증은 같은 트랜잭션에서 확정한다. 동일 txId 재전송은 기존 응답을 재생하고 새 보상 몫을 소모하지 않는다.
- 상품·수량·가중치·칸 위치가 달라지면 새 판의 주기를 시작한다. CSV 행 나열 순서만 바뀌면 유지한다. 같은 판의 저장 횟수가 손상되었으면 지급을 중단한다.

구현은 `functions/src/roulette/rouletteCycle.ts`와 `functions/src/commands/spinRoulette.ts`에 있다. 개발용 `LocalRouletteSpinSource`는 서버 보정의 검증 경로가 아니며 기존 독립 추첨을 유지한다.

검증 스크립트: `functions/scripts/test-roulette-cycle.js`, `functions/scripts/test-roulette-cycle-command.js`. 컴파일된 functions `lib`를 사용하며 `FUNCTIONS_TEST_LIB`로 별도 빌드 디렉터리를 지정할 수 있다.

2026-09-21 서버 함수 `spinRoulette`를 `bm-cardbattle` 프로젝트의 `asia-northeast3`에 배포했다. 서버 보정은 현재 서버 표의 가중치를 사용한다. 보상량을 축소한 CSV의 공식 스펙 업로드는 아직 하지 않았으며 `SpecData.bytes`도 갱신하지 않았다.
