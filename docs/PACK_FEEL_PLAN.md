## 0. 목표

**게임을 처음 깔아 실행한 유저가 5분 안에 직관적으로 "이지한 재미"를 느끼게 한다.** 카드팩 개봉이 그 첫 접점이다.

판단 기준 하나: **유저가 조작법을 배울 필요가 없어야 한다.** 화면을 아무렇게나 건드려도 진행되고, 그 반응이 눈에 보여야 한다.

### 1차 대비 무엇이 바뀌나

| | 1차(현재) | 2차(이번) |
|---|---|---|
| 뜯기 입력 | 3D 콜라이더 위에서 가로로 165px 이상 | **화면 어디든, 아무 방향, 한 번이면 무조건 열림** |
| 조작 안내 | 텍스트("스와이프하여 오픈") | **씰 라이트가 띠를 따라 왕복** |
| 대기 중 팩 | 완전 정지 | **둥둥 플로팅 + 펄스** |
| 개봉 순간 | `SetActive(false)`로 팩이 깜빡 사라짐 | **카메라가 다가가고, 팩이 아래로 빠지며 카드가 드러남** |
| 카드 더미 | UI 카드(Overlay 캔버스) | **3D 카드** (결과 화면만 UI 유지) |
| 넘기기 판정 | 120px 미만이면 되감기 | **떼면 무조건 한 장** |

### 스코프 밖 (이번에 안 함)

- **사운드 · 햅틱** — 전면 제외 (사용자 결정)
- 희귀도(rarity) 도입 — `CardData` 무변경 유지
- 씬 왕복 제거(오버레이화) · "한 번 더" 재구매 · 팩 풀 미리보기 · 확률 표기
- 카메라 셰이크 — 새 개봉 연출과 상충하므로 **제거** 대상

## 1. 착수 전 반드시 읽을 제약

새 세션이 모르면 사고가 나는 것들이다.

### 🚨 `OnAnyPackOpened` 발화 시점을 옮기지 말 것

`PackRevealView.OnAnyPackOpened`는 **튜토리얼(`OutgameTutorialRunner`)의 스텝 완료 신호**다. 발화 시점은 **"뜯기 확정"** = `AnnounceOpened()`. 개봉 시퀀스를 재설계해도 이 의미를 옮기면 튜토리얼이 멈춘다. 스킵 경로(`SkipToSummary`)에서도 반드시 1회 발화해야 한다.

같은 이유로 `PackShowcaseController.OnAnyPurchased`도 불변.

### 🚨 `OnRevealComplete`는 어떤 경로로도 1회 발화

획득 버튼이 이 이벤트로 노출된다(`PackAcquireController.OnRevealComplete`). 미발화 = **씬에 갇힘**. 1차에서 미배선 지점마다 경고 후 다음 단계로 넘기는 설계를 한 이유가 이것이다. 2차에서도 **모든 실패 경로가 요약까지 도달**해야 한다.

### 🚨 `AcquireButton`의 `TutorialAnchor`를 떼지 말 것

`OutgameTutorialBridge.suppressGuideUI`가 CardPack 씬에서 게이트 UI를 억제 중이라, 이 앵커가 억제 모드의 클릭 감지 경로다.

### 🚨 팩은 6장이다

`NormalPack` · `StarterPack_*` 전부 `drawCount = 6`. 3장이 아니다. 3D 스택 겹침 · 결과 격자(3열 2행) 모두 6장 기준으로 설계할 것.

### ⚠️ 연출은 경제를 건드리지 않는다

차감·드로우·소유·환급은 `CardPackOpener.TryPurchase`가 이미 원자 영속했다. 개봉 화면은 `OpenedPack`을 **읽어서 보여줄 뿐**이다. 이번 작업에서 로직 4파일(`CardPackOpener` · `OpenedPack` · `CardPackData` · `PackHandoff`)은 **한 줄도 건드리지 않는다.**

### ⚠️ 1차 문서의 일부 서술은 코드와 어긋나 있다

→ `PACK_OPEN_DIRECTION.md` §3 Stage 3으로 이관됨 (2026-07-28).

## 2. 확정 사양

토론으로 결정된 내용. 담당 세션은 이 사양을 만족시키되, 구현 방식은 스스로 판단한다.

### 2-1. 입력 — "한 번 건드리면 한 단계 진행"

이 화면의 유일한 입력 규칙이다. 뜯기와 카드 넘기기에 **동일하게** 적용한다.

**뜯기**
- 인식 범위: **화면 전역**. 3D 콜라이더 히트 불필요
- 방향: **전방향**. 축 투영(`Vector2.Dot`) 폐기 → 이동 거리로 진행도 산출
- 확정: **포인터를 떼면 무조건 완주.** 임계값·되감기·자동개봉 타이머 전부 없음
- 탭도 동일 — 진행도 0에서 뗀 것이므로 별도 분기 불필요
- 드래그 중 찢김 피드백은 **유지**(판정엔 안 쓰고 표현으로만)
- 완주 시간은 **잔여 진행도에 비례** — 90%까지 그었는데 고정 0.18초를 다 쓰면 늘어진다

**카드 넘기기**
- 떼면 **무조건 한 장** 넘어감. `flickThreshold` · `ReturnHome()` 폐기
- 방향은 유지 — 민 쪽으로 날아감. 이동량이 0에 가까우면 오른쪽 기본값
- **탭 = 한 장 넘김** (기존엔 탭이 전체 스킵이라 오조작 유발)
- **스킵은 버튼 전용**으로 분리

**폐기되는 파라미터**: `commitThreshold` · `rewindDuration` · `flickThreshold` · `Rewind()` · `ReturnHome()` · `OnPointerClick`의 스킵 발화

**부수 효과**: `PackTearHandle`이 Physics 콜라이더와 `Input.mousePosition` 의존에서 해방된다 → 1차 문서가 지적한 **"MainCamera 태그 미설정 시 런타임 무반응"** 리스크도 함께 사라진다.

### 2-2. 아이들 (뜯기 대기)

- **주**: 위아래 플로팅 — 주기 2.4초
  - **바닥 그림자 연동 필수.** 뜰수록 그림자가 작아지고 옅어져야 부유가 성립한다
- **부**: 펄스 — 주기 2.0초. 스케일(1.0→1.03)보다 **광채를 강하게**
- 주기를 어긋나게 잡아 패턴이 안 읽히게 할 것
- **드래그 시작 시 아이들 정지** — 안 그러면 드래그 좌표와 아이들 오프셋이 싸운다

### 2-3. 조작 안내 — 씰 라이트

- 팩의 **띠를 따라 라이트가 좌우 왕복**. 지연 없이 **즉시 시작**(힌트가 아니라 팩의 상시 비주얼)
- 왕복이라 방향을 지정하지 않는다 — **전방향 인식과 의미가 일치**
- **드래그 시작 → 왕복 정지, 라이트가 진행도 위치에 붙음.** 그 지점이 곧 찢기는 자리 (힌트가 피드백으로 전환)
- 기존 텍스트 힌트(`PackRevealView.tearHint`)는 **제거**
  - ⚠️ 이 텍스트는 PKG-PACK-HINT에서 "온보딩이 끝나도 조작법은 필요하다"는 이유로 의도적으로 추가된 것이다. 씰 라이트가 그 역할을 시각적으로 대신하므로 제거하는 것이며, 근거 없이 지우는 게 아니다

### 2-4. 팩 포커싱

- 배경 딤 + 비네트 — 뜯기 단계 진입 시 서서히 조여듦
- 팩 뒤 방사형 광채 — 실루엣을 배경에서 분리
- 느린 배경 입자
- 스펙큘러 스윕 — 주기적으로 빛줄기가 팩 표면을 훑음 (마스킹된 그라디언트 슬라이드로 저비용 구현 가능)

### 2-5. 개봉 시퀀스

**컨셉: 카드 더미에서 팩을 아래로 빼낸다.**

| # | 동작 | 시간 |
|---|---|---|
| 1 | 뜯김 확정 — 팩 내부 발광 최대, 배경 딤·비네트 조임 | — |
| 2 | **카메라 돌리 인** (FOV↓ + 전진), 아이들 정지 | 0.25s |
| 3 | 3D 카드 스택 생성 — 팩 뒤에 가려진 상태 | 0s |
| 4 | **팩 하강**(InCubic) → 카드가 위에서부터 드러남 + **카드 더미 살짝 상승**(상대운동) | 0.45s |
| 5 | 팩 화면 밖 → 비활성 | — |
| 6 | 더미 착지 반동 → 입력 개방 | 0.15s |

총 0.85초 — 현재(`panelFadeDuration 0.35` + `burstHold 0.4` = 0.75s)와 거의 같은 템포.

- **카메라는 Perspective**(`CardPack.unity`, FOV 60) — 돌리 인이 진짜 원근 압박을 만든다
- **"살짝 커진다"를 팩 스케일업으로 하지 말 것.** 시점 집중은 원근 변화이지 크기 변화가 아니다
- `burstEffect` 파티클은 **팩이 빠지며 생기는 틈 라인**을 따라 방출되는 게 인과에 맞다
- 카메라 셰이크는 **제거** (이 연출과 상충)

### 2-6. 카드 계층 — 3D 스택 + UI 결과

**이 분할이 성립하는 이유**: `PackCardStack`과 `PackResultGrid`는 이미 각자 인스턴스를 따로 만들고 서로를 모른다(양쪽 파일 상단 주석에 명시). 그래서 **스택만 3D로 갈아끼우면 결과 격자는 손도 안 댄다.**

**동시에 이것이 Overlay 캔버스 문제의 해법이다**: `CardPack.unity`의 캔버스는 `m_RenderMode: 0`(Screen Space - Overlay)라 **3D 팩이 UI 카드를 가릴 수 없다.** 팩이 카드를 덮어야 하는 이번 연출과 정면충돌한다. 카드를 3D로 옮기면 같은 렌더 계층이 되어 문제 자체가 사라진다. (부가로, Overlay UI에는 카메라 돌리 인이 안 먹으므로 UI 카드였다면 팩만 줌인되어 원근이 어긋났다.)

- **스택 = 3D** — `Assets/Assets/Prefabs/CardView.prefab` 복사본 사용
- **결과 격자 = UI** — `PackResultGrid` · `PackCardView`(UI판) 무변경
- 밀어낸 카드는 **페이드 없이 날려보내기** (3D 원근으로 멀어지며 작아지는 것으로 충분)
- **스택 단계엔 카드 이름을 표시하지 않는다** — 아트만. 이름·상세는 결과 UI에서
- 더미 겹침: 아래 카드일수록 Y 오프셋 + 스케일 축소 → **6장이라는 게 그림으로 읽히게**
  - 현재 값(`stackJitterPos 2f` / `stackJitterAngle 1f`)은 거의 완전히 포개져 장수가 안 읽힌다
- 한 장 밀어낼 때 **아래 카드들이 한 칸씩 올라오며 살짝 커짐**

**3D 전환 시 필수 처리**

| 항목 | 내용 |
|---|---|
| **`SortingGroup` 필수** | `CardView`는 `Card` 하위에 SpriteRenderer가 여러 개 흩어져 있다(`SelectHighlight` order 1, `Left`/`DownArrow_Big` order 0…). 카드 루트에 `SortingGroup`을 붙여 **카드 단위**로 order를 주지 않으면 카드끼리 스프라이트가 섞여 렌더링된다 |
| 입력 좌표계 | `anchoredPosition + canvas.scaleFactor` → `ScreenToWorldPoint` 기반으로 재작성. **Perspective라 카드 평면의 z 거리를 고정**해야 화면 이동량과 카드 이동량이 일치한다 |
| 알파 페이드 없음 | SpriteRenderer엔 `CanvasGroup`이 없다 → **페이드를 안 쓰기로 했으므로 헬퍼 불필요** |
| 재활용 가능한 것 | `CardView`에 `Glow` 파티클(`playOnAwake: 0`, burst 30)과 `SelectHighlight`(비활성 노란 테두리)가 이미 있다 — 신규 카드 강조에 전용 가능 |
| 크기 | 카드 = **2.31 × 3.46 월드 유닛**. 팩이 카드를 감쌌다가 빠지려면 **팩이 이보다 커야 한다** (팩 스케일 조정은 사용자 직접) |

### 2-7. 3D → UI 전환 (결과 화면)

숨기지 말고 **단계 전환 신호로 활용**한다.

마지막 카드를 넘긴 직후 → **카메라가 살짝 후퇴** + 배경 딤 강화 → 그 위로 UI 결과 패널 부상.

레이어가 바뀌는 것이 "손으로 만지는 개봉이 끝나고 정산 화면으로 넘어왔다"로 읽힌다.

⚠️ **3D 카드를 전부 치운 뒤에 UI 패널을 띄울 것.** 겹치면 같은 카드가 두 번 보인다.

### 격리 판정

- **`PackRevealView.cs`가 4개 패키지의 공유 지점**이다. INPUT → 3DCARD → SEQ → OUTRO **순차 진행**하거나 worktree 격리할 것.
- **PKG-FEEL-IDLE만 완전 독립**이다. `PackTearHandle.OnProgress`가 이미 `public event`로 노출돼 있으므로 **구독만 하면 되고 기존 파일을 수정할 필요가 없다.** 아무 때나 다른 세션과 동시 진행 가능.
- **카드 넘기기 입력 규칙은 PKG-FEEL-INPUT이 아니라 PKG-FEEL-3DCARD에서 처리한다.** `PackCardStack`은 3DCARD에서 어차피 폐기되므로, INPUT에서 고쳤다가 버리면 낭비다. INPUT은 **뜯기 + 전체화면 리시버**까지만.

### 착수 순서

```
PKG-FEEL-INPUT ──→ PKG-FEEL-3DCARD ──→ PKG-FEEL-SEQ ──→ PKG-FEEL-OUTRO
PKG-FEEL-IDLE  (아무 때나 병렬)
```

INPUT을 먼저 두는 이유: 체감 개선이 가장 크고, 3D 스택도 리시버 라우팅 위에 얹히기 때문.

## 5. 검수 기준

각 패키지 완료 시 `tcg-reviewer` 게이트 + `Unity_GetConsoleLogs` 컴파일 확인. 추가로 아래를 확인한다.

**공통**
- 로직 4파일(`CardPackOpener` · `OpenedPack` · `CardPackData` · `PackHandoff`) **무변경**
- `OnAnyPackOpened` 발화 시점 = 뜯기 확정, 세션당 정확히 1회 (스킵 경로 포함)
- 모든 실패·미배선 경로가 요약까지 도달하고 `OnRevealComplete` 1회 발화

**Play 검증** — `PackStandaloneBoot`(`alternateDuplicates = true`)로 씬 단독 실행
- 화면 **가장자리·모서리**에서 시작한 스와이프로 팩이 열리는가
- **세로·대각선** 스와이프로 열리는가
- **탭 한 번**으로 열리는가
- 카드 6장이 **6장으로 보이는가**(더미 겹침이 읽히는가)
- 팩이 빠질 때 카드가 **위에서부터 드러나는가** (팩 옆으로 삐져나오지 않는가)
- 3D → UI 전환에서 **같은 카드가 두 번 보이지 않는가**
- 신규/중복 강조가 3D 스택과 UI 결과 양쪽에서 정상인가

## 6. 열린 항목

1차 문서 §6에서 이월 + 이번 결정으로 성격이 바뀐 것들.

- **6장 스와이프 피로.** 1차의 열린 항목이었다. 이번 "무조건 진행" 규칙으로 **탭 6번이면 끝나므로 부담이 줄지만**, 여전히 6번을 요구한다. Play 실측 후 재판단.
- 팩 종류가 늘면 팩별 연출 차등이 필요한가? (`CardPackData`엔 연출 필드 없음)
- 다연차(10연) 계획이 있는가? 있다면 3D 스택 겹침·결과 격자(3열 고정)가 다시 설계 대상.
- 희귀도는 이번에도 도입하지 않는다. 연출 구조는 나중에 등급 강도를 끼울 수 있게 열려 있다(`PlayRevealAccent` 분기).
- 씬 왕복 제거(오버레이화)와 "한 번 더" 재구매 — 리텐션 효과가 크지만 이번 스코프 밖. 별도 설계 세션 필요.
