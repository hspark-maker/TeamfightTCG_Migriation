# 아웃게임 병렬 세션 프로토콜

목적: 사용자가 **여러 세션을 동시에 켜서 병렬 개발**한다. 세션끼리는 서로를 못 보므로 `OUTGAME_BOARD.md`가 유일한 공유 상태다. 이 스킬은 **한 세션이 패키지 하나를 안전하게 claim → 격리 작업 → 반납**하는 절차다. (서브에이전트를 팬아웃하는 스킬이 아니다 — 병렬의 주체는 사람의 여러 세션이다.)

## 1. 무엇을 집을 수 있나 (claim 가능 판정)

`docs/OutGamePlan/OUTGAME_BOARD.md`를 읽고 동시성 등급으로 판정한다:

- **🔴 순차 전용에 `준비`/`진행` 패키지가 있으면 그것부터.** 공유 계약·부트를 동결하는 작업이라 **다른 세션과 동시 진행 금지**. 이게 끝나야 나머지가 안전.
- 🔴이 다 끝났으면:
  - **🟢 병렬 안전** — deps(예: PKG-BOOT) 완료면 다른 세션과 무조건 동시 진행 OK. 독립 파일이라 충돌 없음.
  - **🟠 그룹 내 순차** — 같은 씬/파일 그룹은 **다른 세션이 이미 `진행`이면 집지 않는다**(또는 worktree로 폴더 격리). 그룹 밖과는 병렬 OK.
- 이미 다른 세션이 `진행`으로 잡은 행은 집지 않는다. 확신 안 서면 `architecture-engineer`로 파일·경계 충돌 판정(읽기전용).

## 2. Claim (보드에 표식)

집기로 한 패키지 행의 상태를 **즉시 `진행`(+담당 세션/브랜치 표식)** 으로 바꾸고 저장한다. 다른 세션이 같은 걸 잡지 않게 하는 신호다. (여러 세션이 동시에 보드를 편집할 수 있으니, git 사용 시 보드 변경을 먼저 커밋/푸시하는 걸 권장 — 세션 격리 방식은 사용자 재량.)

## 3. 격리 작업

- 담당 패키지 행 + `OUTGAME_ROADMAP.md`(경계·계약) + 관련 `STRUCTURE.md` 섹션을 근거로 구현한다.
- **동결된 공유 계약(재화·소유·세이브·부트·팩 API)은 소비만, 절대 바꾸지 않는다.** 바꿔야만 진행되면 → 중단·보고(그 작업은 🔴로 재분류 대상).
- 이 세션이 무거운 단건이면, **세션 내부에서** `outgame-engineer`/`cavecrew-builder` 등을 소집하거나 대규모면 `Workflow`를 써도 된다(선택) — 단 이건 이 세션 안의 도구일 뿐, 다른 세션과의 병렬과는 무관.

## 4. 자기 검수 게이트 (반납 전, 각 세션이 자기 것만)

- `tcg-reviewer` 검수(경계·이중 진실원·계약 파손·결정론) + 이 세션 메인이 `Unity_ReadConsole`/컴파일 검증.
- 통과 → 보드 상태 `완료`. 실패 → `진행` 유지 또는 `보류`+사유. Unity Play 통합검증은 사용자 재량(통합 시 일괄 가능).

## 5. 문서 갱신 (반납)

- 구조가 바뀌면 `outgame-visual-recap`(또는 태스크 시각 브리핑)으로 `STRUCTURE.md` 갱신.
- 보드 상태·계약 동결 현황 갱신. 새 계약을 동결했으면(🔴 완료) 계약 동결 표에 반영해 🟢들이 소비 가능해졌음을 알린다.

## 중단 규칙 (즉시 사용자 보고)

- 진행이 **공유 계약을 바꿔야만** 가능 → 중단, 🔴로 재분류.
- 승인된 설계 이탈 / 경계 절대규칙 충돌.
- 집으려는 패키지가 다른 세션 `진행`과 같은 파일 그룹(🟠) → 집지 말고 다른 🟢을 집거나 사용자에게 순서 확인.
