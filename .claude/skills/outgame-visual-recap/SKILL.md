# 아웃게임 시각 정리 (visual recap)

목적: 사용자가 코드를 한 줄씩 읽지 않고도 구조·흐름·원리를 따라올 수 있는 시각 자료를 만든다. 태스크 단위 시각 브리핑(CLAUDE.md 운영 정책)의 확장판으로, 영역·Phase 단위 정리에 쓴다.

## 산출 4종 (모두 `docs/OutGamePlan/STRUCTURE.md`에 반영 + 응답에 표시)

1. **구조 지도** — 대상 영역의 클래스를 레이어/폴더 기준 subgraph로 묶은 mermaid flowchart. 노드에는 클래스명 + 핵심 책임 한 조각(예: `DataSaveManager — static · Load/Save/Data`). 의존 화살표에 관계 라벨(직렬화, flush, 구독 등).
2. **흐름 시퀀스** — 유저/시스템 행동 기준 대표 시나리오 2~3개를 sequenceDiagram으로 (예: 부트 로드, 수확→골드 반영, 구매→소유 부여). 분기(실패·손상 등)는 alt 블록으로.
3. **원리 카드** — "왜 이렇게 생겼는가"를 항목당 3줄 이내로. 반드시 트레이드오프나 규약 근거를 포함 (예: "누적을 double로 두는 이유: 시간당 생산의 소수 손실 방지, 수확 시 정수분만 지급"). 근거 파일:라인 병기.
4. **파일 지도** — 클래스 ↔ 실제 파일 경로 표. 사용자가 다이어그램에서 코드로 점프하는 다리.

## 규칙

- **다이어그램 하나에 노드 15개 이내.** 넘으면 전체 지도(도메인 수준)와 상세 지도(클래스 수준)로 계층 분리한다. 전부 담은 거대 다이어그램은 이해를 돕지 않는다.
- **실제 코드를 Read한 것만 그린다.** 파일:라인 근거 없는 노드·화살표 금지. 미구현 설계는 점선 + (예정) 표기로 구분.
- 시퀀스의 참여자는 5개 이내. 넘으면 시나리오를 쪼갠다.
- STRUCTURE.md 갱신 시 갱신 이력 표에 기록하고, 기존 섹션을 덮어쓰지 말고 해당 영역 섹션을 교체·추가한다.
- 읽기 전용. 이 스킬 수행 중 코드는 수정하지 않는다.
- 형식 기준은 STRUCTURE.md의 "Save·재화 구조" 섹션(첫 정리 예시).

## 확인 마무리

정리 끝에 사용자에게 한 줄로 묻는다: "이 중 더 파고들 부분이 있는지" — 있으면 그 부분만 상세 지도/시퀀스를 추가한다.
