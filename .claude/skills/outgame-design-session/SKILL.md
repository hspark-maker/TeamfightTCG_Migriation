# 아웃게임 도메인 설계 승인 세션

목적: 사용자 승인을 도메인당 1회로 모으고, 그 1회를 "구조도를 보며 제대로" 하게 만든다. 이 세션이 끝나면 개별 태스크는 자율 진행된다(CLAUDE.md 아웃게임 운영 정책).

## 절차

1. **실태 파악** — `docs/OutGamePlan/OUTGAME_ROADMAP.md`에서 대상 도메인의 태스크·경계·규약을 읽고, 관련 기존 코드를 파악한다(필요 시 `cavecrew-investigator` 소집). 추측 금지.

2. **설계안 산출 (코드 작성 금지)** — outgame-engineer 관점으로:
   - 클래스 목록과 각각의 책임 (한 줄씩)
   - 데이터 모델 (필드 수준, 세이브 규약 준수 여부 명시)
   - 태스크 분해: 각 태스크는 독립적으로 구현·확인 가능해야 하고, 로드맵 태스크 번호와 매핑
   - 구현 순서와 의존 관계

3. **자기 비판 라운드** — 설계안에 대해 반드시 답한다:
   - 이 설계가 과설계일 가능성은? 근거는?
   - 프로토타입(재미 검증) 기준으로 더 단순한 대안 2개와, 각각 무엇을 포기하는지
   - 권고안 하나를 명시 (architecture-engineer로 경계·병렬 가능성 판정 필요 시 소집)

4. **구조도 갱신** — 권고안 기준으로 `docs/OutGamePlan/STRUCTURE.md`의 mermaid 구조도를 갱신한다. 기존 승인분과 이번 신규분을 구분 표시(예: 신규 노드에 표식).

5. **승인 요청** — 사용자에게 한 화면 요약으로 제시: 구조도 + 태스크 목록 + 대안 비교표. **승인 전에는 구현을 시작하지 않는다.** 사용자가 대안을 고르거나 수정하면 구조도에 반영 후 재확인.

6. **승인 후** — 태스크 자율 진행 개시. 태스크마다 사전 승인을 묻지 않되, 태스크 완료마다 사람 브리핑 3항목을 남기고, 승인된 설계에서 벗어나는 변경·공유 계약 변경·경계 충돌 시 즉시 중단·보고한다.
